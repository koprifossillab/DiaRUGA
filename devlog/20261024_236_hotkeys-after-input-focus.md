# 236 — 사진을 누르면 입력칸의 초점을 놓는다

2026-10-24 · `work/20261024-sclee-focus`

## 무엇이 고장이었나

검토하던 사용자가 "단축키가 왜 안 듣지" 를 물었다(v0.35.2 운영).

단축키 처리는 초점이 `INPUT`·`TEXTAREA`·`SELECT` 에 있으면 전부 물러난다
(`_detview_js.html` 의 분류·스페이스·화살표·Ctrl+Z 갈래). 입력칸에 글자를 칠 때
단축키가 같이 먹지 않게 하려는 것이라 그 자체는 맞다.

그런데 **사진을 눌러도 초점이 안 옮겨 갔다.** 사진의 `mousedown` 이 끌기·범위
고르기 때문에 `preventDefault` 를 불러, 브라우저가 초점을 옮기는 기본 동작까지
막혔다. 그래서 입력칸을 한 번 쓰고 사진으로 돌아오면 단축키가 죽은 채였다.

예전부터 학명 찾기 칸에서 날 수 있던 일인데, **232 가 속 줄을 단추에서
`<select>` 로 바꾸며 잦아졌다** — 속을 하나 고르면 초점이 목록에 남고, 그 뒤로
분류 키가 안 들으며 화살표는 사진을 넘기는 대신 목록의 속을 바꿨다.

## 한 것

사진(`view`)에 캡처 단계 `mousedown` 하나를 더했다 — 초점이 입력칸에 있고 누른
것이 입력칸이 아니면 `blur()` 한다. 끌기 쪽의 `preventDefault` 는 그대로 둔다
(그것을 걷으면 끌 때 글자가 골라지고 그림이 끌려 나간다).

## 버린 것

- **단축키 쪽에서 `SELECT` 를 거르지 않기** — 목록에 초점이 있을 때 글자 키는
  목록이 쓴다(연 채로 치면 그 이름으로 간다). 막는 자리를 줄이면 그쪽이 깨진다
- **속을 고른 뒤 `change` 에서 목록을 `blur()`** — 속 목록 하나만 고친다.
  학명 찾기 칸·메모 칸에서 사진으로 돌아올 때 같은 고장이 남는다

## 시험

`browser/test_atlas_pane.py` 에 하나 — 속을 고르고 목록에 초점을 둔 채 사진을
누르면 초점이 풀리고, 화살표가 목록을 안 바꾸고, `w` 가 저장 줄을 바꾸는가.
고치기 전 코드로 돌려 "사진을 눌렀는데 목록에 초점이 남았다" 로 실패하는 것을
봤다. Playwright 의 `select_option` 은 초점을 안 남겨 `page.focus` 로 사람이
목록을 누른 상태를 만든다.
