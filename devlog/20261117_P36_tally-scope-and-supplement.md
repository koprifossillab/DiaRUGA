# P36 산출 대상 시야 — 목표에서 끊는다 · 보충 시야 · Eucampia 100

2026-11-17 · sclee · 앞 단계 [P34](20261113_P34_tally-charts.md)·[260](20261115_260_tally-target-attainment.md)(해상도 목표 달성률),
옆 계획 [P35](20261113_P35_eucampia-index.md). 번호는 장부(`~/notes/DiaRUGA/number-ledger.md`)에서
받았다 — P36 · 마이그레이션 0057.

## 1. 왜

260 의 목표(200~400)는 **달성률을 그리는 데만** 쓰였다. 셈은 검토를 마친 시야 전부다 —
RS23-GC03 369 cm 은 856/300 = 285% 로 나온다. 그런데 현미경 개수의 관례는 **목표 수에
닿으면 거기서 멈추는** 것이고, 그 뒤에 찍는 사진은 성격이 다르다:

- **특정 종을 노리고 더 찍는 경우** — P35 의 Eucampia 처럼
- **현장 개수가 목표에 못 미칠까 봐 몇 장 더 확보해 두는 경우**

이것을 같은 셈에 넣으면 노린 종이 부푼다. 그래서 **목표가 세는 범위 자체를 자른다.**
목표 뒤의 시야는 **보충 시야**라 부르고 산출에서 뺀다. 보충 시야는 보통 1장, 많아야 3장이다.

## 2. 사용자가 정한 것 (11-17)

| | 규칙 |
|---|---|
| 차례 | 관찰마다 **g0 부터 시야 번호 순.** 관찰을 이어 붙이지 않는다 — **관찰마다 따로 끊는다** |
| 무엇을 따라가나 | **검토를 마친 시야만.** 중간의 미검토 시야는 **건너뛴다**(멈추지 않는다) — 나중에 마치면 경계가 앞으로 당겨진다 |
| 끊는 자리 | 완형 누적이 목표에 **닿는 시야, 딱 그 시야까지**가 산출 대상. 그 뒤는 전부 보충 시야 |
| 마지막 시야의 완형 | 그 시야 안에서 **개체 번호 순**으로 세다가 목표에서 멈춘다(200 목표면 200번째까지 — 201번째는 밖). 한두 개 어긋나는 것은 큰 그림에서 작은 차이다 |
| 마지막 시야의 파편 | 그 시야에 있는 것은 **전부** 센다 |
| 파편 수 | 산출 대상 시야 범위 안에서만 |
| 미달 | 검토를 마친 시야를 전부 세고 **"미달"** 로 적는다. 통계는 그대로 다 낸다 |
| 해상도 | **지점(코어)에 묶는다.** 저해상도 200 · 고해상도 400 · 기본은 저해상도. **RS14-GC04 는 고해상도** |
| 목표 고르기 | 화면에서 바꿔 볼 수 있게 남긴다(260 의 장점 — "목표를 건드려 보는 길이 귀찮지 않게"). 기본은 지점의 해상도 |
| 전체 | 끊지 않고 검토를 마친 시야를 다 센다(지금의 셈) |
| 직접 입력 | 숫자를 적을 수 있다 |
| **E** | **완형 `eucampia` 유형만** 세어 **100** 에서 끊는다. Eucampia 파편(`eucampia_frag`)은 같은 범위에서 **수를 함께 보이되 100 에는 안 넣는다** |
| 적용 범위 | **산출표 · 산출 그래프 · 산출 비교.** 슬라이드 목록의 개체 수는 검토 진척을 보는 수라 **지금처럼 다 센다** |
| 보충 시야 표시 | 시야 목록(과 검토 화면)에 낸다 — 검토하는 사람이 어디까지가 산출 범위인지 알아야 한다 |

## 3. 말

- **산출 대상 시야** — 끊은 범위 안의 시야. 화면 문구도 이것이다
- **보충 시야** — 그 뒤의 검토 완료 시야. 미검토 시야는 둘 다 아니다(**미검토**)
- **완형** — 세는 분류(`ClassDef.counted`)의 개체. 260 과 같다
- **해상도** — 저해상도(200)·고해상도(400). 목표 **수**와 갈라 부른다: 해상도는 지점의 성질,
  목표는 화면에서 고른 값이다

## 4. 저장 — 마이그레이션 0057 (더하기만)

- `Locality.resolution` — `CharField(choices=[("low","저해상도"),("high","고해상도")])`,
  **`db_default="low"`**(옛 파이프라인 이미지의 INSERT 가 칼럼을 몰라도 들어가게 — CLAUDE.md).
  해상도 → 목표 수 표는 코드 상수(`tally.RESOLUTION_TARGET = {"low": 200, "high": 400}`).
  수를 칸에 넣지 않는 이유: "고해상도" 의 수를 나중에 바꾸면 지점마다 고칠 일이 생긴다.
- 정보 편집 화면의 지점 칸에 고르기 하나. **RS14-GC04 는 배포 뒤 화면에서 고해상도로 바꾼다**
  — 데이터 마이그레이션에 지점 코드를 박지 않는다(테스트 사본·새 설치에서 의미가 없다).
- 파이프라인 이미지는 안 굽는다 — 더하기만이고 `db_default` 가 받는다.

## 5. 세는 법

**셈의 문은 하나로 둔다.** 지금 셈은 `data._SUMMARY_SQL` 이 슬라이드 단위로 접어서 낸다 —
시야·개체 차례가 거기서 사라진다. 끊으려면 **검토 완료 시야의 개체를 한 줄씩**(시야 번호 ·
개체 차례 · 분류 · 종명) 받아 파이썬에서 누적해야 한다.

- 새 질의 하나 — `_SUMMARY_SQL` 의 `cnt`·`rep` 을 그대로 쓰고(완료 시야 · 마지막 완료 묶음 ·
  대표 이미지 하나), 끝만 `GROUP BY` 대신 줄로 낸다. **판정 CASE 를 복사하지 않는다** — CTE 와
  `eff_cls` 식을 상수로 떼어 두 질의가 같이 쓴다. 갈라지면 "전체" 의 수가 지금 화면과 달라진다
- **개체 차례 = 카탈로그 번호 차례** — 그런데 번호의 끝 토막은 **등록 순번이 아니라 자리**다
  (`catalog.position_part` — 엔진 개체는 bbox, 손그림은 그 키). 그래서 "번호 순" 은 사진 위
  **자리 순**이 된다. 등록 순(개체가 생긴 차례 · `DiatomObject.id`)은 사람이 한 번도 안 건드린
  자동 통과 개체에 행이 없어 차례를 못 매긴다. **자리 순으로 정했다**(사용자 11-17) — 누가
  무엇을 고쳐도 안 바뀌고, 카탈로그에서 번호로 정렬한 것과 같다. 손그림은 엔진 개체 뒤
- `tally.scope(rows, goal)` — 관찰 하나의 줄을 받아 `산출 대상 시야 · 보충 시야 · 끊은 자리 ·
  미달 여부` 와 **끊은 뒤의 줄**을 낸다. `goal` 은 `("n", 200)` · `("all",)` · `("E", 100)`
- 끊은 줄에서 `per_cls`·`per_sp`·`n_detected` 를 다시 접어 `column()` 에 그대로 넣는다 — **그 뒤의
  산출표·그래프·CSV 코드는 안 바뀐다.** 파편 비율의 분모(`n_detected`)도 끊은 범위 안의 것이다
- **"전체" 는 지금 셈과 같은 수여야 한다** — 시험이 그것을 잡는다(아래)

E 일 때는 누적하는 것이 완형 전부가 아니라 `eucampia` 분류 개체다. 범위가 정해지면 **그
범위의 산출표 전체**(다른 종 포함)를 그대로 내고, 머리에 `Eucampia n/100 · 파편 m` 을 적는다.

## 6. 화면

- **산출표 · 그래프 · 슬라이드 산출표(261)의 목표 줄** — `지점 설정(200)` · `200` · `300` · `400` ·
  `전체` · `직접 입력` · `E`. 주소 인자 `?target=` 를 그대로 쓴다(`site`·`all`·`E`·정수) —
  **주소가 없으면 지점 설정.** 260 의 "범위 밖이면 400" 은 걷는다 — 직접 입력이 생겼다
- 요약 줄 — `산출 대상 시야 23 · 보충 2 · 미검토 4` · `완형 200/200` 또는 `완형 168/200 미달`
- 산출 그래프 — 시료마다 미달이면 점의 글자에 `미달`. 동정률 패널의 `완형/N` 은 그대로
- **산출 비교** — 열 머리에 목표와 범위(`200 · 시야 23/27`). 목표 고르기는 표 위에 하나
- **시야 목록** — 보충 시야 칸에 `보충` 표지. 기준은 지점 설정의 목표(화면에서 고른 값이 아니다 —
  시야 목록에는 고르는 줄이 없다). 검토 화면 시야 바둑판에도 같은 표지
- 슬라이드 목록·첫 화면의 개체 수 — **안 바뀐다**

## 7. 시험

되살려서 잡히는 것을 보고 "있다" 고 한다(CLAUDE.md).

- 목표 200 · 시야 셋(80·90·50): 셋째 시야에서 30개만 세고 파편은 그 시야 것 전부 · 넷째는 보충
- 미검토 시야를 사이에 둔다 → 건너뛴다. 그 시야를 완료로 바꾸면 경계가 앞으로 온다
- 미달 — 검토 완료 전부를 세고 `미달`
- **`전체` 의 수가 지금 `_slide_summary` 의 수와 같다** — 슬라이드 여럿에서
- E — Eucampia 100 에서 끊고, `eucampia_frag` 는 수에만 있고 누적에는 없다
- 관찰 둘인 시료 — 관찰마다 따로 끊은 뒤 더한다
- 지점 해상도 `high` → 기본 목표 400 · 주소 `?target=` 가 지점 설정을 이긴다
- 0057 앞뒤 — 옛 행이 `low` 를 받는다
