# 217 — 검토 화면에서 시야를 지운다

2026-10-04 · `work/20261004-sclee-ui`

## 1. 왜

검토자가 촬영 순서를 잘못 잡아 쓸모없는 묶음이 시야로 생겼다. 215·216 으로
가르고 합칠 수는 있었지만 **버릴 길이 없었다** — 잘못 찍은 시야가 목록에 남아
검토 대상으로 계속 뜬다.

## 2. 무엇을

`regroup.apply_delete(slide, idx)` — 가르기·합치기와 같은 모듈, 같은 두 걸음
(미리보기 → `confirm=1`), 같은 문지기(읽기 전용 화면에는 단추가 없고, 처리 중인
슬라이드는 서버가 409 로 거절한다). 번호를 다시 매기는 일은 `_rebuild` 에 모든
시야를 `keep` 으로 넘겨 그대로 쓴다.

- **사진(`Frame`) 행은 지우지 않는다.** `SET_NULL` 이라 시야만 떨어져 나가
  그룹핑 전 사진과 같은 모양("어느 시야에도 안 든 사진")이 된다. 폴더에 파일이
  그대로 있으므로 행도 있어야 디스크와 테이블이 맞는다 — `check_db` 의 "원본
  프레임 파일이 있다" 가 그대로 성립한다. 프레임 이미지 행도 `SET_NULL` 로
  시야를 놓는다
- **폴러가 다시 반입하지 않는다.** `scan_nas` 는 폴더 단위(`Slide.image_dir`)로
  새것을 가리고, 다시 묶는 것은 `pending` 일 때뿐이다. 216 의 합쳐진 관찰은 행을
  지우면 폴더가 새것으로 보였지만, 여기는 슬라이드 행이 그대로라 그 문제가 없다
- **슬라이드를 `processing` 으로 돌리지 않는다.** 새로 만들 시야가 없다.
  가르기·합치기와 달리 지운 뒤에도 바로 검토를 이어 간다
- **마지막 시야는 못 지운다.** 시야 0개인 `done` 관찰은 검토할 것이 없는 빈
  행이 되고, 되돌릴 길도 없다. 관찰째 없애는 것은 정보 편집 화면의 일이다
- 지운 뒤에는 그 자리에 이제 놓인 시야로 보낸다(끝을 지웠으면 앞 시야)
- `Run(kind="group")` 에 지운 시야의 `tag` 와 사진 이름 목록을 남긴다 — 무엇을
  버렸는지 되짚을 근거다

**시야 안의 일부 사진만 버리는 칸은 따로 두지 않았다.** 가르고 나서 떨어진
쪽을 지우면 되고, 칸을 하나 더 두면 가르기 칸과 생김새가 겹쳐 215 같은 혼동이
다시 난다.

## 3. 시험

`test_regroup.py` 에 넷 · `PostOnlyTest` 에 `delete_group`. 렌더한 화면에서
지우기 단추의 주소를 찾아 미리보기 → 확인으로 보내고, 사진 행이 남는지·번호가
빈틈없는지·상태가 `done` 인 채인지·`Run` 에 사진 목록이 남는지 본다. 마지막 시야
검사를 빼 보면 `test_마지막_시야는_못_지운다` 가 실패하는 것을 봤다.

## 4. 남은 것

- **되돌리는 길이 없다.** 사진 행은 남아 있으므로 "어느 시야에도 안 든 사진을
  새 시야로 묶는" 화면을 낼 수 있지만, 쓰일지 보고 정한다. 지금은
  `group_focus_series.py --force` 뿐이고 그것은 슬라이드 전체를 다시 묶는다
