# 240 — 한국 도감 도판 512 항목을 그림별로 자른다

2026-10-25 · sclee · 앞의 것은 [239](20261025_239_paper-plate-crops-four.md)(논문 넷 크롭) ·

## 무엇을

한국동식물도감 제9권 도판 53장(Plate 21–74, PDF 41–269)에서 **도감 항목 512개
전부의 그림을 하나씩 잘랐다.** 크롭이 있는 종이 도감 전체에서 **462 → 896** 이 됐다
(학명·하위종 글자가 같으면 한 종으로 센 값 · 2,290 종 중 · 백업 사본에 반입해 셌다).
남은 1,394 종은 거의 Schmidt 다.

- `tools/crop_atlas_figures.py` — 번호 좌표 → 덩어리 → 크롭 → `Diadiction/plate/`
- `atlas/korean_crop_fixes.toml` — 기계가 틀린 자리를 사람이 고친 것(31쪽 81건, 쪽마다 근거)
- `atlas/korean_pages.toml` 의 `[plate_fix]`·`[plate_fill]` — **색인의 `pl.` 가 실제
  도판과 다른 49항목**(아래). `tools/parse_atlas.py` 가 읽어 덮는다
- `tools/parse_atlas.py` — 한국 항목에 `crop_image` 를 채운다
- `tools/sync_paper_plate_images.py --only korean` — 뷰어 쪽(`/data3`) 복사

마이그레이션은 없다(`crop_image` 는 0042).

## 왜 `crop_plates.py` 를 안 썼나

161 의 도구는 상자마다 **그림 번호를 사람이 적는다**(`ASSIGN`). 논문은 그림 번호와
학명의 짝을 캡션에서 따로 옮겨야 해 그럴 수밖에 없었다. 한국 도감은 **그림 번호가
곧 항목 번호이고 그림 바로 아래에 찍혀 있다** — 번호의 좌표만 있으면 짝이 정해진다.
사람은 기계가 틀린 자리만 고치면 된다. 시제품 4쪽에서 34개 중 32개가 맞아 이 길로 갔다.

## 번호 좌표 — 두 갈래

- **텍스트 레이어가 있는 37쪽** — `pdftotext -bbox`. 함정 셋을 만났다:
  번호가 조각으로 갈린다(`40 3` · `22 0`) · 마침표 붙은 `405.` 가 쪽 가운데에 찍혀
  캡션 윗변을 끌어올렸다 · **쪽 한 구석을 통째로 덮는 가짜 글자 상자**(p93 은
  14–298 × 83–345pt). 셋째가 가장 나빴다 — 크롭 단계가 "글자 안의 잉크는 그림이
  아니다" 하고 지워서 **277 의 왼쪽 절반이 예외 없이 사라졌다.** 다섯 쪽에 있었다.
  20pt 넘는 글자 상자는 버린다
- **없는 16쪽**(191–269) — **사내 OCR 서버는 못 썼다.** `data-bbox` 가 블록 단위라
  번호 하나하나의 좌표가 안 나온다(P21 · 175 와 같은 결론). 대신 37쪽의 번호
  상자에서 **숫자 견본 1,000개를 떼어 상관계수로 읽었다.** 진짜 번호는 글자마다
  0.77 이상, 그림 속 줄무늬는 0.30 이하라 문턱(0.6)에서 깨끗이 갈린다. GPU 도
  새 패키지도 안 썼다(파이프라인 이미지의 cv2, 17쪽에 12초)

## 덩어리를 번호에 붙이는 규칙

1. 번호가 덩어리 상자 **안**에 있으면 그것 — Chaetoceros 판은 번호를 강모 사이에 찍는다
2. 아니면 **아래쪽** 가장 가까운 번호(가로 여유 30pt)
3. 번호가 둘 걸린 덩어리는 팽창을 줄여 다시 가른다(15 → 7 → 3 → 1). 닿은 원 셋이 하나였다
4. 그림 상자 안에 통째로 든 주인 없는 조각은 그 그림의 속 무늬다
5. 크롭에서 **남의 번호에 붙은 잉크·남의 번호 글자·버린 덩어리는 흰색으로 지운다**

자동으로 맞은 비율은 쪽마다 크게 갈렸다. 선그림 원반·피침형 판은 거의 다 맞고,
**Chaetoceros·Rhizosolenia 판**(강모가 서로 닿고, a·b·c 부분 그림이 번호 없이 흩어진다)
에서 대부분의 손질이 나왔다.

## 사람이 고친 것 — 근거는 본문의 형태 서술

번호가 안 찍힌 부분 그림이 누구 것인지는 **쪽만 봐서는 안 갈린다.** 애매한 15곳을
해설 본문의 형태 서술로 갈랐다 — 예: p131 의 비틀린 띠는 349(Streptotheca "비틀려진
엽상 군체"), p190 의 정방형 격자 조각은 479("격자 모양은 정방형"), p209 의 두 타원은
543(크기만 다른 같은 모양 · "긴 타원형 30~80μ"). **본문으로도 안 갈린 다섯은 `"-"` 로
뺐다** — 틀리게 붙이는 것보다 낫다(201 · 209 · 231 · 254 · 45 의 잔점). 쪽마다 근거를
`note` 에 남겼다.

## 색인의 `pl.` 가 틀린 49항목

번호를 512개 전부 읽고 나니 **실제로 놓인 도판과 색인의 `pl.` 가 Plate 69–74 에서
어긋났다.** 색인 탓이 아니라 **책 본문의 인쇄**다 — 색인은 본문을 충실히 옮겼다
(641 의 본문 p.253 이 "pl. 71" 인데 그림은 Plate 69 에 있다).

| 갈래 | 항목 | 본문 | 실제 |
|---|---|---|---|
| 2 밀림 | 638–678 의 39개 | 71–74 | 69–72 |
| 色圖 | 553·594·599·614·622·657·679 | 70 | 74 (같은 판의 500·529 는 본문도 74) |
| 따로 | 668 | 37 | 71 |
| pl. 없음 | 347 (본문 텍스트 레이어가 `p!. 46`) · 680 (설명이 발췌 밖) | — | 46 · 72 |

147 은 "Plate 69 는 아무 항목도 안 부른다" 고 적었는데, **부르는데 번호가 밀려 있었던**
것이다. 그때 화면의 「도판」 링크가 이 49항목에서 두 판 옆 쪽을 열고 있었다.

**색인 원문은 안 고쳤다**(P15 4.2 · 147 의 `[[typo]]` 와 같은 방식). `korean_pages.toml`
에 표로 두고 `parse_atlas.py` 가 `plate` 를 덮으며 원래 값을 자리의 `note` 에 남긴다.
**표의 `index` 는 색인에 적힌 값이다** — 색인이 바뀌어 다르면 반입이 멈춘다.

## 버린 것

- **OCR 서버** — 위. 블록 좌표로는 번호 하나를 못 짚는다
- **GPU(SAM)** — 사용자가 허락했지만 쓸 자리가 없었다. 선그림·흰 바탕이라 연결
  성분으로 충분했고, 틀린 것은 경계가 아니라 **어느 번호의 것인가**였다
- **사람이 상자마다 번호를 적기**(`crop_plates.py` 방식) — 512개를 다 적는 대신
  틀린 81건만 적었다

저쪽은 작업 디렉터리에 초안만 냈다.

## 확인

- 크롭 512 = 항목 512 (빠진 것·겹친 것 0). 쪽마다 번호 집합 = 색인(정정 뒤)의 집합
- 크롭 512장 전수 눈검사(28장씩 격자 19장) — 잘림·남의 조각·지우기가 파먹음·번호
  불일치 넷을 봤다. **문제 0.** 의심했다가 원본과 대조해 정상으로 판정한 것이 열하나
  (원본 그림이 끊겨 있거나, 한 번호에 그림이 여럿인 판)
- 백업 사본에 `import_atlas.py` 두 번 — 도감 19 · 항목 2,748 · 자리 4,002 로 같다.
  `/atlas/?q=` 에 한국 크롭 칩과 정정 `note` 가 뜨고 `/img?p=` 가 200
- `python3 tools/test_parse_atlas.py` — 61개(정정표 6개 더함 · 정정 코드를 빼면 깨지는 것을 봤다)
- `python web/manage.py test viewer --exclude-tag browser` — 1,096개
