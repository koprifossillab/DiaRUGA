검토 대상을 `yolo-4차` 로 옮기기 **전에** 들어가 있어야 하는 것을 넣었다(P31 6절).

## 3. 버린 것 · 바꾼 것

- **빈 칸 규칙을 "검출이 있는 가장 최근 묶음" 에서 "검토 대상이 그 시야의 권역을 다루면
  그것" 으로 바꿨다.** 처음 규칙이면 4차를 기다리는 남극 시야(RS14-GC04 — `sam2-전수`
  검출만 있다)가 SAM 편집 화면으로 열렸다. 기존 시험(`test_coverage_gap`)이 잡았다.
  권역은 `batch_scope.allows` 하나로 본다 — 4차 조리법의 `areas: ["ant"]` 가 한국 새
  슬라이드를 `sam2-전수` 로 보낸다. Smear 의 새 관찰은 P29 6절 5(`exclude_obs`)가
  들어가야 같은 길을 탄다 — 그 전에는 "4차 검출이 없습니다" 화면이 된다
- **시야 객체에 주 묶음을 캐시하지 않는다** — 같은 객체를 쥔 채 검토 대상을 갈면 옛
  답이 남았다(시험이 잡았다). 한 시야에 질의 서넛이고 화면은 0.07~0.17초다
- **가르기·합치기·지우기는 칸에 얼린 묶음이 적힌 정답 시야만 막는다.** 칸이 빈 시야도
  얼린 검토 대상을 따라가면 잠기는데, 거기까지 막으면 RS14-GC04(7 → 12 시야로 갈라야
  한다 · 215)를 못 가른다. 지킬 정답이 없는 시야다
- **칸이 빈 잠긴 시야를 "정답" 이라 부르지 않는다** — "다음 회차의 검출을 기다립니다"
- **검토 화면이 전역 묶음으로 prefetch 하던 것** — `group_detail` 이 `_viewpoints_of(…,
  only_current=True)` 로 전역 검토 대상의 검출만 당겨 와서, 주 묶음이 다른 시야는
  `current_detections` 가 고를 것이 없었다. 응답은 200 이라 **화면을 그려 보기 전에는
  모른다** — 086 과 같은 종류다. 시험(`test_검토_화면이_주_묶음의_검출을_그린다`)이
  되살려 잡는다

## 4. 시험

3겹 1,134개(얼림·주 묶음·산출·`check_db` 39개 새로) · 브라우저 7개 새로. 잠금 장치마다
**꺼서 실패하는 것을 봤다**(서버 잠금 넷 · JS 배선 셋 · 산출 SQL 둘 · 오프라인 둘 · prefetch
하나). 완료 없이 산출을 세던 기존 시험 넷은 새 규칙에서 **0 == 0 으로 헛통과**할 자리라
완료를 걸고 0 이 아님을 함께 본다.

## 5. 배포 때 볼 것

- `0052` 는 더하기만이라 **파이프라인 이미지를 안 굽는다**(옛 이미지의 INSERT 는 칸을
  비운 채 들어간다 — 그것이 "따라간다" 다)
- 배포 직후 **`check_db` 14번** — 둘 다 OK, 알림에 "칸이 빈 시야 64개" 가 떠야 한다
- **목록·산출 비교의 숫자가 바뀐다**(2절). 보고서에 실린 숫자와 비교할 일이 있으면 이
  표를 본다
- **`yolo-3차` 가 얼어서 남극의 칸이 빈 64 시야도 잠긴다**(369cm 12 · 369cm_100 38 ·
  RS14-GC04 14) — 4차 검출 위에서 검토하기로 한 것들이다(P29 4절). 문턱 적용도 막힌다

## 6. 남은 것

- 4차 검사 출력을 3차 정답 시야에 읽기 전용으로 겹쳐 보이기(P31 ⑤) · 재현율 화면(P31
  5절 4) — 4차 검출이 생긴 뒤
- **명령줄 `refilter.py` 는 얼림을 모른다** — 파이프라인 이미지의 옛 모델로 돌아 `frozen`
  칸이 없다. 얼린 묶음에 돌리지 말 것(뷰어의 문턱 적용은 막았다)
- 학습 자료 화면(`training_overview`)과 문턱 화면은 여전히 전역 검토 대상을 본다 — 앞엣것은
  `export_yolo.py` 가 `--batch` 로 못 박아 화면과 갈릴 수 있다
- 검토 화면의 분류 단축키(q·w·e …)는 얼린 시야에서 안 듣는다 — 유형은 카탈로그 칸의
  고르개로 바꾼다
