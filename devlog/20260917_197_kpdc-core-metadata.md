## 2. 빈 칸만 채운다 — 063 의 그 줄

`group_focus_series` 가 폴더 이름으로 지점을 만들면 코드 하나뿐이고
좌표·수심·채취일은 사람이 관리 화면에서 채운다. KPDC 값으로 채우되
**`lat`·`lon`·`water_depth_m`·`collected_at`·`collect_kind` 는 비어 있을 때만
쓴다.** `WAP13` 처럼 사람이 넣은 값이 옳고 KPDC 가 대략값인 경우가 실제로
있으므로, 자동값이 사람의 것을 덮는 길을 애초에 안 만든다(`sample_fields` 가
`None` 을 defaults 에 안 싣는 것과 같은 줄).

**짐작으로 채우지도 않는다.**

- 좌표는 `Spatial Coverage` 가 **POINT 하나**일 때만. 옛 `RS14-GC04` 항목처럼
  POLYGON 이면 꼭짓점 하나를 코어 위치라 할 수 없다
- 채취일은 `Research period` 가 **하루짜리**일 때만. `2014-02-01 ~ 2014-02-28`
  을 첫날로 적으면 그날 떴다는 말이 된다
- 채취 방식은 장비가 `GRAVITY CORER`·`BOX CORER`·`PISTON CORER` 일 때만
  `gravity core`·`box core`·`piston core`. `SEDIMENT CORERS` 는 비워 둔다

`kpdc_id`·`kpdc_meta` 두 칸(마이그레이션 `0044`)은 이 모듈의 것이라 다시
긁으면 갈아치운다. `kpdc_meta` 에 페이지에 노출된 것 전부가 JSON 으로 든다 —
파일에 두지 않고 DB 에 두는 이유는 백업이 같이 나르고 화면이 바로 읽기
때문이다(첨부 몇 개가 있는지를 지점 카드에 적는다). `kpdc_id` 는
`db_default=""` — 옛 파이프라인 이미지의 INSERT 가 그대로 돈다.

**항목이 둘이면 Entry ID 가 큰 것.** `RS14-GC04` 가 2014년 항차 직후 것("Old
ID")과 2024년 재등록 것 둘이고, 새것이 좌표·수심·길이를 갖고 있다. 제목에서
코어 이름은 **낱말 단위**로 본다 — `RS21-GC03` 이 `RS21-GC03B` 를 줍지 않게.

## 3. 사내 DNS 가 이 호스트를 모른다

이 서버의 리졸버가 `kpdc.kopri.re.kr` 을 NXDOMAIN 으로 돌려준다(`www.kopri.re.kr`
도 같고 `kopri.re.kr` 만 사내 주소 `172.16.200.31` 로 풀린다 — split-horizon).
바깥 리졸버(8.8.8.8)는 `203.250.180.198` 로 푼다. 컨테이너도 호스트의 상위
DNS 를 물려받으니 같다.

그래서 `viewer/kpdc.py` 의 `fetch()` 는 **이름이 안 풀리면 IP 로 붙고 TLS
SNI·Host 헤더는 이름으로 준다** (`http.client.HTTPSConnection` 을 한 줄
덮어썼다). IP 는 `DIARUGA_KPDC_IP` 로 바꾼다. 표준 라이브러리만 쓴다 — 뷰어
이미지에 `requests` 가 없고, 이것 하나 때문에 넣을 일이 아니다.

읽기 시간 초과는 **한 번 더 해 본다** — 사본으로 열 지점을 돌리는데 하나
(`RS14-GC04`)가 30초를 넘겼다. 한 번의 실패로 그 지점이 `--missing` 에 남는
것보다 재시도 하나가 싸다.

## 4. 절차에 넣은 자리

`deploy/poll_nas.sh` 의 **그룹핑 성공 직후**다 — 지점이 방금 만들어져 칸이
비어 있는 순간. `rundb "$T_SCAN" fetch_kpdc.py --slide "$slug"` (dbtool 문,
뷰어 이미지, torch 없음).

**실패해도 폴러를 멈추지 않는다.** 바깥 서버라 사내망 사정에 매이고, 항목이
아직 등록 전일 수도 있다(`RS23-GC03` 은 항차 7개월 뒤에 등록됐다) — 반입이
서는 조건이 아니다. `warm_thumbs.sh` 와 같은 갈래다. 못 긁은 것은
`dbrun.sh fetch_kpdc.py --missing` 으로 나중에 다시 돈다. 시험이 그 실패 갈래에
`continue`·`exit` 가 없는 것을 본다.

이미 `kpdc_id` 가 있는 지점은 스크립트 안에서 건너뛴다 — 같은 코어의 두 번째
슬라이드가 들어와도 KPDC 를 다시 안 부른다. 다시 긁는 것은 `--force`.

## 5. 배포 뒤에 할 것

판을 올린 **뒤에** 스크립트를 `/srv` 로 민다 — 먼저 밀면 칼럼이 없어 폴러
로그에 실패 줄만 쌓인다.

**파이프라인 이미지는 안 굽는다.** `0044` 는 더하기뿐이라 옛 이미지의 모델은
그 칼럼을 모르고(SELECT 도 안 한다) INSERT 는 `db_default` 가 받는다. 같은 날
옆 세션이 넣은 `schema_guard`(198)도 **이미지의 모델이 아는 칼럼·테이블이 DB
에 있는가**를 보지 마이그레이션 번호를 대조하지 않는다 — 칼럼을 걷거나
옮기는 판만 파이프라인을 같이 굽는다(그때는 guard 가 세운다).

```bash
/srv/DiaRUGA/bin/deploy.sh v0.27.0            # 0044 가 붙는다
deploy/host/sync_to_srv.sh                    # poll_nas.sh
deploy/host/dbsync.sh fetch_kpdc.py
deploy/host/dbrun.sh  fetch_kpdc.py --missing --dry-run
deploy/host/dbrun.sh  fetch_kpdc.py --missing # 빈 지점 7개를 채운다
```

사본 dry-run 실측: 10개 중 9개 긁힘(1개 시간 초과 → 재시도를 넣었다).
`RS19`·`RS21-GC03B/04/05`·`RS23` 은 좌표·수심·채취일·채취 방식이 다 채워지고,
`AM22`·`RS21-GC02` 는 사람이 이미 넣은 좌표를 두고 나머지만, `GC03-C1`·`WAP13`
은 채울 빈 칸이 없다. **`RS21-GC02` 의 채취일이 `2021-10-05` 로 들어가 있는데
그것은 KPDC 등록일이다**(채취일은 2020-12-13) — 사람이 넣은 값이라 안 덮는다.
관리 화면에서 고칠 것.

- **`Locality` 에 칸을 안 만들고 `note` 에 적는 것** — 사람의 메모와 자동값이

  드문 일이라 그때 한 번이면 되고, 남은 것은 손으로
- **요청이 필요한 첨부까지 받는 것** — 로그인·공개 요청이 필요하다. 받으면
  `Download` 인 것과 같은 자리에 두고 P17 로 간다

## 7. 내려받을 수 있는 것은 받는다 — `GC03-C1` 을 P17 로 반입했다

사용자가 이어서 청했다 — "Download 되는 xlsx 도 받아서 P17 로 반입해 줘.
다운 되는 것은 다운 받는다고도 적고."

**화면의 「Download」 버튼이 하는 것을 그대로 한다.** 첨부 행의
`data-file-id` 로 `POST /rawdata/<id>/` 에 용도(`purpose`)를 실으면 302 로
일회용 주소가 오고 그것을 GET 하면 파일이다. 쿠키도 로그인도 없다. 두 번
헛짚었다:

- **Referer 가 항목 페이지가 아니면 POST 자체가 500** 이다
- **302 를 POST 로 따라가면 400** 이다 — `curl -X POST -L` 이 그렇게 한다
  (`-X` 가 리다이렉트에도 메서드를 강제한다). 헤드리스 브라우저로 실제
  흐름을 잡아 보고 나서야 알았다. `_request()` 는 리다이렉트를 **GET 으로**
  따라간다

`fetch_kpdc.py` 가 `Download` 인 첨부를 `<DATA_ROOT>/coredata/kpdc/<지역>-
<지점>/` 에 받고 `kpdc_meta.files[].saved` 에 자리를 적는다(`--no-download`
로 끈다). 이미 같은 크기로 있으면 다시 안 받는다. **첨부 하나를 못 받아도
메타데이터는 저장한다.** 지점 카드의 첨부 줄이 `첨부 14개 · 받아 둠 1 ·
요청 필요 13` 처럼 갈린다.

**받았다고 반입되는 것은 아니다.** 어느 열이 무엇이고 깊이 단위가 무엇인지는
P17 의 규칙대로 사람이 `coredata/mapping.toml` 에 적는다. `GC03-C1` 은 이렇게
갔다:

- xlsx 는 논문 *Incorporation of Multi-elements into Diatom Frustules in the
  Scotia Sea* 의 자료 — **규조 각 속 원소 농도**(µg/kg) 71개 + 연대(ka).
  시트 하나, 깊이 칸이 `GC03-C1 14` 꼴이라 추출기에 `depth_prefix` 를
  더했다(적힌 접두사만 뗀다 — 아무 글자나 벗기면 `LOD` 줄이 숫자로 읽힌다).
  3행 `LOD` 는 깊이 칸이 비어 저절로 빠진다. 음수는 LOD 아래 — 원본 그대로
- 원본은 NAS `coredata/` 에 같은 이름으로 복사했다(P17 의 원본 자리).
  중간 CSV 는 `/data3/DiaRUGA/tmp/coredata/`(전체)와 `tmp/coredata-gc03/`
  (이번 반입분)
- 사본 DB 로 먼저 돌려 화면(`/loc/GC03/C1/`)이 200 인 것을 보고, 운영에는
  `backup_db.py --note before-gc03-coredata` 를 뜬 뒤 `dbrun.sh
  import_coredata.py --dir /data3/DiaRUGA/tmp/coredata-gc03` — **항목 72 ·
  점 2,016** · `check_db` OK · 화면 200 (09-17 15:07)

**`kpdc_id`·`kpdc_meta` 는 아직 운영에 없다** — `0044` 가 든 판을 배포한 뒤
`fetch_kpdc.py --missing` 이 채운다(5절). 그때 `GC03-C1` 의 xlsx 를 다시
받는다 — 같은 크기라 파일은 그대로고 `saved` 만 적힌다.
