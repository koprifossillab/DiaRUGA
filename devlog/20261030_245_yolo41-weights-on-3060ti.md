# 245 — 4.1차 가중치 둘을 운영 3060 Ti 에서 재다: 지금 코드로는 빽빽한 시야가 빠진다

2026-10-30 · paleoadmin · [242](20261028_242_yolo4-training.md) 남은 일 4 의 실측

242 가 정한 기준은 "**11l 이 문제없으면 11l, 하나라도 걸리면 11m**" 이고 볼 것은 셋이다 — 원본
해상도 이미지가 8 GB 에 드는지 · 장당 시간 · 폴러와 공존. 셋을 쟀고, **둘 다 같은 자리에서
걸렸다.** 걸린 자리는 가중치가 아니라 `segment_diatoms.py` 의 YOLO 갈래가 마스크를 만드는 방식이다.

## 1. 어떻게 쟀나

- **운영과 같은 것으로** — 파이프라인 이미지 `v0.5.3`(torch 2.13.0+cu126 · ultralytics 8.4.7) 컨테이너,
  `segment_diatoms` 의 YOLO 갈래와 같은 인자(`imgsz=1280 · conf=0.01 · retina_masks=True · fp32` — 운영은
  `half` 를 안 준다. 025 는 fp16 으로 쟀다), 같은 후처리(상자 둘레만 CPU 로 · `generate`)
- **OOM 도 운영처럼** — 첫 시도가 모자라면 `except` 밖에서 비우고 한 번 더, 또 모자라면 건너뛴다(그 이미지는
  검출이 0 이 된다)
- GPU 잠금(`/data3/DiaRUGA/locks/gpu.lock`)을 잡고 돌았다 — 폴러와 안 겹친다. 재는 동안 GPU 에 다른 것은 없었다
- 합성본 **25장**(2208×2752) — 3차 검출 수로 정렬해 고르게 10장 + 가장 빽빽한 15장(3차 통과 32~74개 ·
  369cm 이 대부분). 4차는 합성본에만 돌린다(P31 ①) — 합성본이 없는 시야의 한 장도 같은 해상도다
- 가중치: NAS `models/yolo-v4.1/` 의 둘(`39b06590…` · `dce919de…` · `SHA256SUMS` 통과)과, 비교용으로 지금 운영의
  3차 11m(`11m-v1seg-1280` · `d9e20a26…`)
- 측정 스크립트는 저장소 밖 scratchpad 에 있다(`probe.py` · `equal.py`) — 운영 코드는 안 고쳤다

## 2. 지금 코드 그대로 — 빽빽한 시야가 빠진다

| 가중치 | 25장 중 건너뜀 | 장당 (추론 + 후처리) 가운데값 |
|---|--:|--:|
| 3차 11m (지금 운영) | 9 | 202 ms |
| 4.1차 11m | **15** | 133 ms |
| 4.1차 11l | **17** | 150 ms |

**4.1차는 빽빽한 15장 대부분을 검출 없이 건너뛴다** — 4차가 가장 크게 나아진 자리(빽빽한 시야의 재현율 ·
242 2절)가 통째로 빠진다. 장당 시간이 짧아 보이는 것은 무거운 이미지가 빠져서다.

**운영에서 이미 일어나고 있다.** 실행 기록(10-28 사본)에서 `yolo-3차` 검출 44번 중 9번이 `partial` 이고,
첫 시도 OOM 34장 중 25장이 재시도로도 안 들어가 건너뛰어졌다. CLAUDE.md 의 "8 GB 카드에 안 들어가는 프레임이
1,318장 중 1장" 보다 훨씬 많다.

**까닭** — `conf=0.01` 이라 검출이 상한(`max_det=300`)까지 차고, `retina_masks=True` 는 ultralytics 의
`process_mask_native` 가 **그 마스크를 전부 원본 크기로 한꺼번에** 만든다(검출마다 float32 24 MB · 상자 밖을
지우는 곱셈이 같은 크기를 몇 벌 더 만든다). 모델 크기와 거의 상관없다 — 11l 이 11m 보다 더 많이 빠지는 것은
더 많이 잡아서다.

## 3. 버린 것 — 설정으로는 안 풀린다

같은 25장 · 1회:

| 4.1차 | `conf` | fp16 | `expandable_segments` | 건너뜀 11m / 11l |
|---|--:|---|---|--:|
| | 0.01 | | 켬 | 15 / 17 |
| | 0.01 | 켬 | | 15 / 17 |
| | 0.05 | | | 5 / 5 |
| | 0.10 | | | 3 / 2 |
| | 0.25 | | | **1 / 1** |

- **조각화 설정과 fp16 은 효과가 없다** — 메모리를 쓰는 것이 마스크라 모델 쪽을 줄여도 안 된다
- **`conf` 를 올리면 줄지만 0.25 에서도 1장(369cm g073)이 빠진다.** 그리고 `conf` 를 낮게 두고 뽑아 DB 에서
  다시 고르는 것이 지금의 방침이다(`segment_diatoms` 의 YOLO 갈래 머리말 · 025 §8)
- `retina_masks=False` 는 값을 바꾼다(CLAUDE.md) — 안 봤다

## 4. 나눠 만들면 풀린다 — 값은 바이트까지 같다

`process_mask_native` 는 검출마다 독립으로 계산한다(계수 × 프로토타입 → bilinear 보간 → 상자 밖 지우기 →
0/1). 그래서 **검출을 몇 개씩 나눠 불러 이어 붙여도 결과가 같다.** 측정 스크립트 안에서만 16개씩 나눠 부르게
바꿔 끼웠다.

- **같은가** — 원래 함수와 나눈 함수로 같은 이미지를 두 번 돌려 마스크·상자를 `torch.equal` 로 비교했다. 검출
  1~86개짜리 6장이 **전부 같았다**(7장째에서 원래 함수 쪽이 OOM 으로 멈췄다 — 비교 스크립트에는 재시도를 안 넣었다)
- **들어가는가** — `conf=0.01` 그대로:

| 가중치 | 25장 중 건너뜀 | 검출 가운데 · 최대 | 추론 가운데 · p90 | 후처리 | 장당 합 | 메모리 최고 (torch · nvidia-smi) |
|---|--:|--:|--:|--:|--:|--:|
| 3차 11m | **0** | 99 · 248 | 108 · 127 ms | 143 ms | 248 ms | 6,614 · 6,904 MiB |
| 4.1차 11m | **0** | 137 · 300 | 125 · 174 ms | 110 ms | 267 ms | 7,056 · 7,346 MiB |
| 4.1차 11l | **0** | 155 · 300 | 148 · 193 ms | 166 ms | 327 ms | 7,466 · 7,756 MiB |

  (3회 · 25장. 4개씩 나눠도 건너뜀 0 · 최고 7.4 GB 안팎으로 거의 같다 — 보이는 최고치는 PyTorch 가 잡은 메모리를
  안 놓고 쌓아 두는 값이라 카드 한도 쪽으로 붙는다)

## 5. 기준에 대면

| | 11m | 11l |
|---|---|---|
| 8 GB 에 드는가 — 지금 코드 | 아니오(15/25 빠짐) | 아니오(17/25 빠짐) |
| 8 GB 에 드는가 — 나눠 만들면 | 예 | 예 (여유가 11m 보다 ~0.4 GB 적다) |
| 장당 시간 | 0.27 초 | 0.33 초 — 합성(시야당 10초 · 025)에 비하면 둘 다 작다 |
| 폴러와 공존 | GPU 잠금으로 차례로 돈다 · 이 카드를 쓰는 다른 것은 없다 | 같다 |

**11l 에만 걸리는 것은 없다** — 걸리는 것(지금 코드의 OOM)은 둘 다 걸리고, 나눠 만들면 둘 다 풀린다. 그래서
**기준대로면 11l** 이다. 다만 메모리 여유가 11m 보다 좁아서, 마스크를 나눠 만드는 고침을 넣은 뒤 **4차 재검출의
첫 슬라이드(369cm 같은 빽빽한 것)에서 `oom` · `oom_retry_ok` 를 본다** — 건너뜀이 나오면 11m 으로 내린다.

## 6. 남은 일

1. **`segment_diatoms.py` 의 YOLO 갈래가 마스크를 나눠 만들게 한다** — 가중치와 상관없이 4차 재검출 전에
   있어야 한다. 파이프라인 코드라 **파이프라인 이미지를 새로 굽는다**(P29 6절 4 의 `judge.py` 가 YOLO 클래스를
   읽는 일과 한 판에 싣는다). 고칠 자리는 ultralytics 함수를 바꿔 끼우는 것이라 ultralytics 를 올릴 때 함께
   본다(`requirements-yolo.txt` 와 같은 줄)
2. 고친 판으로 이 25장을 다시 돌려 **운영 코드 경로로** 건너뜀 0 을 확인한다(지금 숫자는 측정 스크립트의 것이다)
3. 3차 때 건너뛰어진 25장은 4차 재검출이 다시 돈다 — 따로 할 일은 없다
