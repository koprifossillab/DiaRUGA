# 229 — 검토 화면을 넓게 쓰고 세 칸으로 가른다

2026-10-21 · `work/20261021-sclee-ui` · sclee · 사용자와 미리보기를 주고받으며 잡았다
(테스트 자리 `/DiaRUGATest/` 에 `v0.33.4-229pre1`~`pre9` 를 차례로 걸었다)

## 왜

사용자: "검토 화면이랑 데이터셋을 볼 때 화면을 GSM 처럼 넓게 보고 싶어. 지금처럼 양 옆을
비울 필요는 없잖아." 본문에 `max-width: 1500px` 이 걸려 있어 넓은 창에서는 양옆이 비었다.

다른 프로젝트의 화면과 검토 도구들(EcoTaxa·CVAT 등)을 먼저 훑어봤다. 검토 방식을 바꾸는
제안들(확신도 순 정렬·한꺼번에 확정)은 **사용자가 접었다** — 애매한 개체는 등급으로 가르고,
바라는 것은 **화면 디자인**이었다.

## 무엇을

### 넓히기

- 목록·슬라이드·검토 화면만 `main.wide` 로 상한을 푼다. 글을 읽는 화면(설정·도감 등)은 그대로다
- 폭에만 맞추면 2560 창에서 사진 높이가 1,700px 이 되어 아래를 스크롤해야 했다 — **사진이 창
  높이 안에 다 들어오게** 가운데 칸 폭을 잡는다(`--ar` = 사진 가로/세로, `.detrow` 에 실린다)
- **프레임 줄도 창 안에 남긴다**(사용자). 판을 넘기는 자리라 늘 보여야 한다
- 줄 높이를 창에 못 박는다(`100vh - 116px`). 안 그러면 왼쪽 바둑판(시야 62개)이 줄을 늘려
  사진 칸까지 창 밖으로 밀린다. 탭 줄 오른쪽 요약은 한 줄로 자른다 — 두 줄로 접히면 사진이 밀린다

### 세 칸 — [왼쪽] [사진 + 프레임 줄] [오른쪽]

처음에는 교정 도구까지 왼쪽 칸으로 뺐는데 사용자가 **"화면 조정 외 주요 도구들은 기존처럼
오버레이로 두자"** 고 해서 되돌렸다. 그리기·되돌리기·레이어는 사진에서 눈을 안 떼고 누르는
것들이다.

| 칸 | 위 | 아래(바닥) |
|---|---|---|
| 왼쪽 | 화면 조정 · **시야 바둑판**(이 슬라이드 전부, 지금 시야 테두리, 검토 끝난 시야 초록 점) · 검토율 막대와 통계 | 조작·단축키 안내 |
| 가운데 | 사진(도구 오버레이 그대로) | 프레임 줄 — **사진 밑에만**, 화면 폭 전체를 안 먹는다 |
| 오른쪽 | 개체 카탈로그 · **도감** | 선택 정보·저장 상태 · 오프라인 꺼내기 · 시야 가르기 |

- **바둑판은 `leave()` 로 떠난다** (116: 떠나는 자리는 전부 그 문으로). 다른 엔진을 보는
  중이면 링크가 `?batch=` 를 들고 간다. 숫자는 시야 목록 화면과 같은 집계(`_slide_summary`)다
- **도감 칸은 가벼운 검색 + 도판 한 장**(사용자가 골랐다 — 도감 화면을 통째로 들이는 쪽을 접었다).
  카탈로그 종명 자동완성과 같은 문(`api/atlas/suggest`)을 쓰고, 개체를 고르면 그 종명으로 찾는다.
  **종명 칸에 `input` 을 쏘면 저장이 나가므로** 따로 `catspecies` 이벤트를 알린다. 검색창 밑에
  **속명 한 줄**(많은 순 · 옆으로 구른다)
- **오프라인 꺼내기·가르기를 `group.html` 에서 떼어 `_view_actions.html` 로.** 오른쪽 칸에
  놓이는 것은 `actions_here` 를 받는 include 하나뿐이고, 읽기 전용·검출 없음 갈래에서는 예전처럼
  사진 아래 놓인다. **한 화면에 한 번만** — `<details>` id 가 겹치면 안 된다. 027 의 조건(읽기
  전용에서 가르기 감춤)은 조각 안에 그대로 있다. 펼치면 칸 위로 띄워 사진 쪽으로 넓게 연다

### 칸 여닫기·폭 (사용자)

탭 줄 오른쪽 끝에 `◧ ⬓ ◨ ↺` — 왼쪽 칸·프레임 줄·오른쪽 칸 감추기와 기본값. 칸 사이 손잡이를
끌어 폭을, 사진과 프레임 줄 사이 손잡이로 썸네일 크기를 바꾼다(두 번 누르면 그 하나만 기본).
**보는 방식이라 브라우저에만**(`diaruga.layout`) — 밝기·대비와 같은 자리다. 프레임 줄 높이가
썸네일 폭을 따르므로 사진 칸 높이 계산(`--dv-room`)도 그것을 따라간다.

## 함정 — 실제로 밟은 것

- **flex 항목의 기본 최소 폭은 내용이다.** 속명 한 줄(줄바꿈 없음, 수천 px)이 오른쪽 칸을
  화면 끝까지 밀었다. 세 칸에 `min-width: 0`
- **도구를 옮기면 그것을 찾는 시험이 조용히 빈다.** `test_coverage_gap` 은 `if tools is not
  None` 으로, `test_readonly` 는 `query_selector_all` 로 찾아 — 자리를 옮기자 **아무것도 안
  보고 통과**했다. 둘 다 "없으면 실패" 로 고쳤다(도구는 결국 제자리로 왔지만 구멍은 남아 있었다)
- 그리기 시험 20개가 `#dv-stack button[data-act="draw"]` 로 연필을 찾는다 — 도구를 칸으로
  뺐을 때 전부 시간 초과로 죽었다. 되돌리면서 시험도 원래대로다
- `git checkout` 으로 한 파일을 되돌렸다가 그 위에 얹은 `--ar` 줄을 잃었다 — 2560 에서만
  사진이 창을 넘어 알아챘다
