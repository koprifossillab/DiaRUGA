## 1. 이름 — `yolo-4차` 가 아니라 `yolo-4.1차`

P29 는 `yolo-4차` 묶음이라 적었지만, 운영 가중치로 고른 것은 **4.1차 11l**(`models/11l-v41seg-1280.pt` · 246)이다.
4차 첫 판 가중치로 돌린 묶음이 아니므로 이름도 4.1차로 한다(사용자 10-30). 코드는 묶음 이름에서 차수를 안 읽는다
— 이름은 화면과 `data-batch` 에만 나간다.

## 2. 조리법

```
{"backend": "yolo", "weights": "/data3/DiaRUGA/models/11l-v41seg-1280.pt", "scale": 1.0,
 "yolo_conf": 0.01, "yolo_imgsz": 1280, "min_um": 10.0, "max_um": 150.0,
 "areas": ["ant"], "exclude_obs": ["Smear"]}
```

- `all_images` 없음 — **합성본에만**(합성본이 없는 시야는 그 한 장) · P29 6절 끝(사용자 10-28)
- conf·크기 구간은 3차(046)와 같다
- 묶음은 첫 슬라이드를 `--batch yolo-4.1차` 로 돌려 만들고 `batch_recipe.py --restore` 로 조리법을 얹었다 —
  **이제 폴러가 새 남극 슬라이드를 이 묶음에도 채운다**(묶음 표 1번 · 검토 대상 `yolo-3차` 는 조리법이 비어 안 돈다)

## 3. 돌린 것

**`--keep-current` 없이** 돌렸다. 현재 표시는 **같은 묶음 안에서만** 옮겨지고(`_promote_and_rebind` · P10), 재바인딩은
`(이미지, 묶음)` 의 교정만 본다 — 새 묶음에는 교정이 없어 아무것도 안 한다. `--keep-current` 로 쌓으면 4.1차 안에
현재 검출이 없어 8단계(검토 대상을 옮긴다)에서 화면이 빈다.

## 4. 아무것도 안 흔들었는가

재검출 전·후 사본(`manual/…_155108_before-yolo41-redetect.db` · `…_155556_after-yolo41-redetect.db`)을 비교했다:

- 다른 묶음의 현재 검출 — `sam2-전수` 654 · `yolo-3차` 2,247, id 합까지 같다
- 교정 — 행 수 · id · 바인딩이 같다
- 시야의 주 묶음 칸(`Viewpoint.batch`) — 같다
- 화면 — 369cm 목록·검토·카탈로그 200 · smoke 통과 · 검토 화면 묶음 상자에 `yolo-4.1차` 가 하나 더 놓인다

`check_db` 에 **새 경고가 하나** — "검출이 있는 묶음에 카탈로그 코드가 있다: `yolo-4.1차`". 묶음 코드
(`RunBatch.code` · 번호의 꼬리 `…-Y3`)는 **라벨에서 뽑지 않고 사람이 정한다**(모델 주석) — 정하기 전까지 4.1차
개체는 번호가 없다. 검토 대상이 아직 3차라 화면에서 번호가 빠지는 자리는 묶음 상자로 4.1차를 열었을 때뿐이다.
