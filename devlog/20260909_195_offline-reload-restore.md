# 새로고침해도 적어 둔 것이 화면에 남는다 (195)

194 를 내면서 범위 밖으로 떼어 `TODOs.md` 의 「지금 가장 급한 것」에 적어 둔
자리다. **폰에서 이 판을 실제로 쓰기 시작하면 가장 먼저 부딪힌다.**

## 무엇이 고장이었나

편집은 `localStorage` 에 남는다(`_offline_shell.html` 의 `EDITS`). 그런데
**그것을 화면에 되살리는 코드가 없었다.** 검토기·동정기 둘 다 `onpaint` 가
목록의 ✓ 와 테두리만 바꾸고, 마스크·분류·종명은 구울 때 박아 둔 값 그대로다.

- 검토기 — `initDetView` 가 구운 태그(`cand-`·`gone-`·`rej-`·`acc-`·`lab-` ·
  `shotdet-`)를 읽어 상태를 세운다. 그 태그는 **꺼낸 시점의 것**이다
- 동정기 — 카드의 값이 `value`·`dataset` 에 박혀 있다

**데스크탑에서는 새로고침이 드물어 안 드러났다.** 폰은 큰 문서를 문 탭을 수시로
버린다 — 파일 하나가 수십 MB 라 더 그렇다.

## 왜 조용히 잃는가

돌아오면 지운 마스크가 살아 있고 적어 둔 종명이 빈 칸으로 보인다. 여기까지는
사람이 알아챈다. **문제는 그 다음이다** — 그 자리에서 이어 검토해 저장하면
기록이 그 판의 줄을 통째로 갈아치운다(`record` 의 "한 표적에 한 줄"). 화면이
모르는 것은 안 실려 나가므로 **아까 한 판단이 결과 파일에서 사라진다.**

`/review` 가 "뷰어는 늘 전체를 보낸다" 를 전제로 도는 것과 **같은 줄**이다
(017·027·116). 다른 것은 여기서는 서버가 아니라 **화면 자신이 그 전제를
깼다**는 것뿐이다.

## 어디서 되살리나 — 구운 자료를 고치고 배선을 부른다

`initDetView` 안으로 들어가 상태를 만지지 않았다. 그 파일은 **온라인 화면과
함께 쓰는 것**이고(189 가 배선을 하나로 모은 이유), 교정을 읽는 규칙이 두
벌이 되면 조용히 어긋난다.

그래서 **판을 처음 열 때, 배선을 부르기 직전에 구운 태그를 고친다.**

```
show(gid) → 사진 붙이기 → applyEdits(gid) → initDetView(uid)
                            └ 구운 태그를 기록으로 맞춘다
```

하는 일은 **서버가 다시 그렸다면 그렸을 모양**으로 맞추는 것이다
(`data._apply_review` 와 같은 규칙). 규칙이 둘이면 새로고침 전후가 달라진다.

| 기록 | 되살리는 자리 |
|---|---|
| `removed` | 통과분 ↔ 유령을 가른다 (`gone` 의 키가 곧 `removed`) |
| `accepted` | 탈락분에서 통과분으로 옮기고 `from_reject` 를 붙인다 |
| `labels` | 지도를 갈아 끼우고 개체의 `cls`·`cls_user`·`cls_auto` 도 맞춘다 |
| `drawn` | 구운 손그림을 **전부 걷고** 기록의 것을 넣는다 |
| `edits` | 폴리곤을 얹고 `bbox`·`center` 를 다시 잰다. 빈 배열은 표시만 걷는다 |
| 카탈로그 | `species`·`grade`·`pose`·`note` 를 개체에 얹는다 |

**판마다 따로다.** 기록의 열쇠가 `시야|판` 이라 처음 열리는 판(태그 넷)과
캐러셀이 갈아 끼울 판들(`shotdet-`)을 각각 제 기록으로 맞춘다 — 시야로만
짚으면 프레임의 교정이 합성본에 얹힌다(P09 1단계와 같은 이야기).

### 밟은 자리 넷

- **그린 개체는 기록이 전부다.** 구운 것에 남아 있는 손그림을 안 걷고 기록의
  것을 더하면, 지운 그림이 되살아나고 같은 개체가 둘이 된다. **지운 것은
  `drawn` 에 없다** — 그것이 지웠다는 말이다(P09 5.10)
- **되살렸다가 되돌린 것**은 탈락분으로 돌아가야 한다. 구울 때 통과분에 있었고
  기록의 `accepted` 에 없는 것이 그것이다. 안 되돌리면 되살리기를 무른 개체가
  계속 통과분에 앉아 있다
- **되살린 것에 `from_reject` 를 안 붙이면** 다음 저장에 안 실린다 — 화면의
  되살리기가 그 표를 붙이는 것과 같은 이유다(`restore` 의 주석)
- **동정기의 유형은 `dataset` 으로 되돌린다.** 아래에서 `select` 목록을 짜며
  `card.dataset.cls` 를 읽으므로, 칸에 직접 넣으면 짜는 자리에서 지워진다

## 확인 — 되살려서 잡히는 것을 보고 나서 적었다

브라우저 겹에 여덟을 더했다(`tests/browser/test_offline_reload.py`).
**이 겹이 아니면 볼 수 없다** — 3겹 시험은 구워 낸 글자를 보는데, 여기서
깨지는 것은 *두 번째로 열었을 때* 화면이 무엇을 그리는가다. 파일은 한 글자도
안 바뀐다.

되살린 자리를 걷어 내고 돌리면 **여덟 중 일곱이 죽는다.** 남는 하나는
`test_브라우저가_기억한다` 인데, 그것은 `file://` 의 `localStorage` 가 막히면
나머지 일곱이 **못 잡는 시험**이 되는 것을 가르는 자리다(아무것도 안 남은 것을
"복원 안 됨" 으로 읽는다).

**가르지 못하는 시험을 둘 고쳤다.**

- 하나만 지우고 Ctrl+Z 로 되돌리면 기록이 빈 목록이 되어, 되살리기가 고장 나
  있어도 통과한다(구운 자료에 지운 것이 원래 없다). **둘을 지우고 하나만
  되돌린다**
- 동정기에서 구울 때 박힌 유형과 **같은 값**을 고르면 되살리기가 없어도
  통과한다. 다른 값을 고른다

## 남겨 둔 것

**목록의 ✓ 와 테두리 아래 표(개체 목록)는 서버가 그린 판 그대로다.** 판을
바꿔도 안 바뀌는 것과 같은 자리이고(`swapDet` 의 주석), 이번에도 안 고쳤다 —
그 표는 읽을거리이지 교정이 붙는 자리가 아니다. 개수는 배선이 고쳐 적는다.
