# 오프라인 검토기·동정기 (계획)

사용자 요청 (2026-09-07): "검토 페이지를 표시하는 html 을 만들어서 특정
슬라이드나 특정 범위의 시야 데이터만 오프라인 html 파일로 추출, 동정이나
검토를 수행하고 해당 html 의 데이터를 다시 여기에 제공하면 그 데이터를 가지고
검토 데이터를 업데이트."

정한 것 (같은 날 문답):

| 물음 | 답 |
|---|---|
| 무엇을 할 수 있나 | 동정(개체 카탈로그) · 검토(지우기·되살림·유형) · 마스크 그리기·고치기 |
| 파일 단위 | **프로그램이 둘이다** — 개체 동정기(크롭 위주) · 시야 검토기(슬라이드 하나까지) |
| 되돌려 넣는 길 | 뷰어 화면에 올린다 (미리보기 → 적용) |
| 쓰는 자리 | 가끔 붙는다 (현장·이동 중만 오프라인) |
| 범위 | **어느 슬라이드의 어느 시야**를 꺼낼지 고른다 |

## 1. 왜 화면을 두 벌 만들지 않는가

검토 화면의 JS 는 `_detection.html` 안에 4,292줄 중 3,900줄로 들어 있다.
확대·이동 · 마스크 그리기 · 폴리곤 고치기 · 단축키 · 겹친 개체 고르기 ·
탈락 펼침판 · 실행취소 · 판별 색까지 전부 거기 있고, **그 코드가 교정의
의미를 들고 있다**(`keyOf` 가 서버의 `data.cand_key` 와 같아야 하고,
그린 개체는 `labels` 지도에 실으면 안 되고, 지운 것은 흔적으로 남아야 한다).

오프라인용으로 다시 쓰면 그 규칙이 두 벌이 된다. **두 벌이 되면 어긋나고,
어긋나면 조용히 어긋난다** — 038(분류 여덟 칸)·053(프레임 이름)이 그
모양이었다. 그래서 **같은 화면을 그대로 쓴다.**

서버에 매달린 자리는 다섯뿐이다 (실측):

| 자리 | 온라인 | 오프라인 |
|---|---|---|
| 사진 `src` | `{% thumb %}` → `/img?p=…` | **data: URI** (번들이 싣는다) |
| 크롭 `src` | `ROOT + '/crop?…'` | **캔버스로 그 자리에서 자른다** (사진이 이미 있다) |
| `/review` | fetch | **기록해 둔다** |
| `/catalog/save` | fetch | **기록해 둔다** |
| `/spread` · `/link` | fetch | **아예 막는다** (아래 3.3) |

그래서 1단계는 **저 다섯을 환경 객체 하나로 모으는 것**이다. 온라인 동작은
한 줄도 안 바뀌고, 오프라인이 그 객체를 갈아 끼운다.

## 2. 단계

| | 무엇 | 확인 |
|---|---|---|
| 1 | `_detection.html` 의 `<script>` 를 `_detview_js.html` 로 떼고 `initDetView(uid)` 로 만든다. 서버에 닿는 다섯 자리를 `window.DiaRUGA.env` 로 모은다 | 시험 1,044개 (브라우저 188 포함) 그대로 통과 |
| 2 | `viewer/offline.py` — 슬라이드·시야 범위 → 번들. `/offline/` 고르기 화면과 `POST /offline/export` | 파일 하나가 떨어지고 크기가 예고한 대로다 |
| 3 | 오프라인 **검토기** HTML — 시야 넘기기 · 저장 기록 · 결과 내려받기 | 브라우저 시험이 `file://` 로 열어 지우고 유형 바꾸고 내려받는다 |
| 4 | 오프라인 **동정기** HTML — 크롭 카드에 종명·등급·자세·코멘트 | 같은 방식 |
| 5 | 반입 — `POST /offline/import` (미리보기) → `apply=1` (적용). 충돌 검사 | 사본 DB 에 넣어 본다 |
| 6 | 시험을 갈래대로 채운다 | 아래 6절 |

## 3. 오프라인 파일의 모양

### 3.1 자족적이어야 한다

`base.html` 은 이미 자족적이다 — CSS 도 로고(SVG)도 파비콘(data:)도 전부
인라인이고 바깥 파일을 하나도 안 부른다. 그래서 오프라인 파일은 **같은
`base.html` 을 그대로 쓴다.** 다만 머리줄의 링크(데이터셋·Atlas·톱니)는
오프라인에서 갈 곳이 없으므로 `offline` 표시로 감춘다 — **눌러도 아무 일도
안 일어나는 것**을 남기지 않는다(063 계열).

**「오프라인 사본」 워터마크를 늘 얹는다.** `Test Server` 와 같은 자리·같은
이유다: 이 화면을 운영으로 알고 검토하면 그 교정이 아무 데도 안 남는다.

### 3.2 무엇이 실리나

| | 검토기 | 동정기 |
|---|---|---|
| 그림 | 시야마다 **합성본 한 장**(1600px JPEG) | 개체마다 **세운 크롭**(320px) |
| 자료 | 후보·탈락·교정 상태·µm/px·분류 정의 | 카드 자료(번호·종명·유형·등급·자세·코멘트) |
| 크기 | 시야 30개 ≈ 10~15 MB | 개체 500개 ≈ 8 MB |

**프레임은 안 싣는다** — 시야당 5~7장이라 파일이 다섯 배가 된다. 판이
하나뿐이면 `swapDet` 이 곧장 빠져나가 캐러셀 없이 그대로 돈다(이미 그렇게
설계돼 있다). 필요해지면 그때 옵션으로 연다.

> **덧 (2026-09-07 · 같은 날 뒤집혔다 → 191).** 사용자: *"프레임 다 담아야돼 ·
> 프레임 하나만 보고 개체를 어떻게 동정을 해."* 맞다 — 초점 시리즈를 넘겨 보는
> 것이 동정의 방법이고, 그것을 뺀 파일은 **가벼운 대신 쓸 수 없다.** 프레임을
> 다 담고, 대신 **크기를 재서 미리 알린다**(실측 · `offline.VIEW_PX`).
> 해상도도 사람이 고른다 — 온라인은 확대하면 원본으로 갈아 끼우는데
> (`maybeHiRes`) 오프라인은 파일에 든 것이 전부다.

### 3.3 오프라인에서 **막는 것**

`/spread`(마스크를 다른 판에 앉히기)와 `/link`(같은 개체 묶기)는 **판이
여럿일 때의 일**이라 합성본 한 장만 실은 파일에서는 뜻이 없다. 저장을
막는 것으로 끝내지 않는다 — **도구를 화면에서 뺀다**(051 이 정확히 그
자리다: 저장만 잠그고 우클릭 메뉴를 살려 뒀다가 한 시야를 헛검토했다).

### 3.4 결과 파일 — **마지막 상태만 담는다**

요청을 순서대로 다 쌓지 않는다. 같은 시야를 열 번 만지면 열 줄이 쌓이고,
미리보기가 무엇이 바뀌는지 말해 주지 못한다. **표적 하나에 한 줄**이다:

```json
{"diaruga_offline": 1, "kind": "review",
 "bundle": {"id": "...", "slide": "rs23", "batch": 12, "gids": [0,1,2],
            "made_at": "2026-09-07T09:00:00Z"},
 "saved_at": "...", "by": "검토자 이름(자유)",
 "edits": [{"gid": 3, "image": 51,
            "was": "<그때 서버 상태의 지문>",
            "payload": {"removed": [...], "accepted": [...], "labels": {...},
                        "drawn": [...], "edits": {...}, "done": true}}]}
```

`payload` 는 **온라인 화면이 `/review` 로 보내던 것 그대로**다. 반입은 그것을
`data.save_review` 에 그대로 넘긴다 — 저장하는 규칙이 둘이 되지 않는다.

## 4. 반입 — 두 걸음, 그리고 지문

`/review` 는 **그 판의 교정을 통째로 갈아치운다**(027·017). 오프라인 파일은
어제의 상태 위에서 만든 것이라, 그 사이 누가 온라인에서 같은 시야를
검토했으면 **그 판단이 통째로 사라진다.**

그래서 번들이 판마다 **지문**을 싣는다 — 그때 서버가 들고 있던 교정 상태
(removed·accepted·labels·drawn·edits, 동정기는 카드 넷)의 해시다. 반입 때
다시 재서:

| | 뜻 | 기본 |
|---|---|---|
| 지문이 같다 | 그 사이 아무도 안 만졌다 | **적용한다** |
| 지문이 다르다 | 온라인에서 누가 만졌다 | **건너뛴다** — 무엇이 다른지 적고, 사람이 골라야 덮어쓴다 |
| 후보 키가 달라졌다 | 재검출이 돌았다 | **거절한다** — 사람이 고를 수도 없다(짚을 자리가 없다) |
| 묶음이 다르다 | 검토 대상 묶음이 바뀌었다 | **거절한다** |

첫 POST 는 무엇이 바뀌는지 **보여 주기만** 하고, `apply=1` 이 실린 두 번째
POST 만 쓴다 — `split_group` 과 같은 두 걸음이다.

## 5. 주소

```
GET  /offline/                     고르기(슬라이드·범위·프로그램) + 올리기
POST /offline/export               파일 하나를 내려보낸다 (attachment)
POST /offline/import               미리보기 · apply=1 이면 적용
GET  /d/<slug>/offline/            그 슬라이드로 채워 놓은 고르기 화면
```

## 6. 시험 — 무엇을 되살려서 잡나

**커버리지가 아니라 함정 목록이다** (CLAUDE.md).

- 1단계가 온라인을 안 깨뜨렸나 — 기존 브라우저 시험 188개가 그대로 증인이다
- 오프라인 파일이 **바깥을 하나도 안 부르나** — 렌더 결과에 `http`·`/img?`·
  `/crop?` 로 나가는 `src`·`href` 가 없다(있으면 현장에서 백지가 된다)
- 지문이 다를 때 **적용되지 않나** (사본 DB 에 다른 교정을 넣고 반입)
- 후보 키가 달라졌을 때 **거절하나**
- 결과 파일이 빈 `removed` 를 실었을 때 — 그것이 "지운 것이 없다" 로 읽히고
  **그 판의 교정을 지우는가**(017 이 그 자리다). 지문이 같으면 그것이 옳다
- 그린 개체(`m…` 키)가 오프라인에서 만들어져 반입되나
- 오프라인 화면에서 `/spread`·`/link` 도구가 **화면에 아예 없나**(051)
