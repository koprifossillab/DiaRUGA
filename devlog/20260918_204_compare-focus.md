# 산출 비교 — 중요한 수만 남기고, 종을 골라 보고, 코어의 Opal 을 곁에 둔다

**작성일** 2026-09-18 · 사용자 "산출 비교 페이지가 나쁘진 않은데, 무엇이
중요한 정보인지 모르는 것 같아서 표시해야 되는 정보를 알려줄게"

---

## 202 가 놓친 것

202 는 축을 뒤집는 데까지였다 — 열이 슬라이드, 줄이 분류 → 종명. 사용자가
본 것은 그 표가 **무엇이 중요한지를 모른다**는 것이었다. 검토 수가 시야 수와
같은 무게로 머리에 있고, 종명이 없는 나머지가 줄로 서고, 비율 막대는 선
색이라 안 보였다. 그리고 산출을 읽는 사람이 바로 옆에 놓고 싶은 것 —
**그 층준의 Opal** — 이 아예 없었다.

사용자가 준 목록을 그대로 옮긴다. 이것이 이 화면의 요구 사항이다.

| 사용자 말 | 한 것 |
|---|---|
| 종명 없음은 표시할 필요 없어 | 「종명 없음」 나머지 줄을 걷었다 |
| 모든 종의 수를 표시할 필요는 없고, 오른쪽 위에 비교 대상 — 산출 종 전부 체크박스로, 특정 종만 보이게 | 표 오른쪽에 「비교 대상」 판 |
| 검토가 끝난 슬라이드를 비교하는 거니까 검토 수는 필요 없고 시야 수만 | 머리에 시야 수만 크게 |
| 시야당 검출 수(파편 제외) | `n_counted ÷ 검출이 돈 시야` |
| 전체 검출 수 중 파편의 비율(퍼센트) | `파편 ÷ 남는 개체 전부`, `61.9% 205/331` 꼴 |
| 그래프를 넣을 거면 각 급간의 상징색으로 강조라도 해. 안 보여 | 막대를 `ClassDef.color` 로 |
| 해당 층준의 Opal 을 참조해서 표시(그래프로), 없으면 인근을 내삽, 코어 자료 자체가 없으면 데이터 없음 | 「코어 자료」 줄 — 잰 값 · `≈` 내삽 · 범위 밖 · 데이터 없음 |
| 비교 대상이 적을 때는 칸 폭을 넓혀 쪽에 맞춰 | `table-layout: fixed` + `width: 100%` |

## 결정한 것

### 거르는 것은 화면 안에서만 — 분모는 안 건드린다

「비교 대상」 판의 체크박스는 표의 **줄**을 감출 뿐이다. 수·비율은 그대로다
— 종 둘만 남겨 놓았다고 그 둘의 합이 100 % 가 되면 그것은 다른 표다. 분류를
끄면 그 아래 종명 체크박스를 잠근다(켜 봐야 줄이 안 뜬다). 주소에는 안
싣는다 — 202 가 "주소가 곧 비교" 로 정한 것은 **무엇을 놓느냐**이고, 무엇을
가리느냐는 보는 사람의 손이다. 지도 모드의 「보일 슬라이드 고르기」(203)와
같은 층인데 그쪽처럼 `localStorage` 에도 안 남긴다 — 표를 열 때마다 전부
보이는 것이 맞다(가려 둔 채 다음에 열면 "종이 사라졌다" 가 된다).

표와 판이 **같은 `rows` 를 같은 차례로 돌아** `data-cls`·`data-sp` 를 만든다.
종명의 열쇠는 이름이 아니라 `<분류>-<차례>` 다 — 이름에는 빈칸·마침표가
있고 속성값에 그대로 넣으면 선택자가 깨진다.

### 열 머리의 수 셋 — 시야 · 시야당 개체 · 파편 비율

분모가 서로 다르다는 것이 핵심이라 머리말에 적어 두었다.

- **시야당 개체** = 세는 분류의 합 ÷ **검출이 돈 시야**. 시야 전부가 아니다 —
  검출이 안 돈 시야를 분모에 넣으면 밀도가 낮게 나온다. 시야 전부보다 적으면
  `19/34` 꼴로 머리에 같이 보인다.
- **파편 비율** = `counted=False` 분류의 합 ÷ **남는 개체 전부**(파편·미분류
  포함). 미분류는 파편이 아니다(`is_fragment` 머리말) — 분자에 안 든다.

검토 수(`reviewed_groups`)는 자료에서도 뺐다 — 슬라이드마다
`done_viewpoints` 를 한 번씩 부르던 질의도 같이 사라졌다.

### 막대는 분류의 색이다

202 는 "뜻 있는 색을 빌리지 않는다" 며 선 색을 썼는데, 그 결과가 **안
보이는 막대**였다. 분류의 색은 뜻 있는 색이 아니라 **그 분류의 색**이다 —
검토 화면의 마스크·카탈로그의 표시가 이미 같은 색이라 표에서도 같은 것을
가리킨다. `ClassDef.color`(`r,g,b`)를 `--c` 로 내려 `rgba(var(--c), .38)` 로
깐다. 종명 줄은 같은 색을 `.2` 로. 두 테마에서 글자가 그 위에 읽히는 것을
눌러 봤다.

막대는 **왼쪽부터** 자라고 수도 왼쪽에 둔다. 202 는 오른쪽부터였는데 열이
넓어지자 수(왼쪽)와 막대(오른쪽)가 떨어져 다른 것처럼 보였다. `base.html` 이
셋째 열부터 오른쪽 정렬이라 둘째 열만 다르게 서 있던 것도 이때 잡았다.
100 % 막대가 옆 칸의 막대와 이어져 보이지 않게 오른쪽 12 px 는 비운다.

### 코어 자료의 참조값 — 내삽은 하되 지어내지는 않는다

`data.core_value_at(pts, depth_mm)` 이 갈래 넷을 낸다.

| 상태 | 언제 | 화면 |
|---|---|---|
| `exact` | 그 깊이에 잰 점이 있다 | `44.0 %` |
| `interp` | 양옆에 점이 있다 | `≈ 45.5 %` · 툴팁에 어느 두 깊이 사이인지 |
| `outside` | 잰 범위의 밖 | 「범위 밖」 · 툴팁에 범위 |
| `none` | 항목이 없다 · 깊이가 없다(노두) | 「데이터 없음」 |

내삽은 **양옆 점의 선형**이다. 범위 밖은 한쪽 점만 보고 늘여 그리면 없는
값을 지어내는 것이라 안 한다 — `_segments` 가 빈 구간을 가로지르지 않는
것(P17)과 같은 태도다. 사용자 말의 "인근 코어 데이터를 내삽" 이 이 자리다.

항목은 `COMPARE_CORE_KEYS = ("opal",)` 하나다 — Opal 은 규조 껍질(생물기원
규산)의 양이라 산출과 바로 견주어 읽는 값이다. 더 얹을 항목이 생기면 이
목록에 더한다. 점은 **지점마다 한 번만** 읽는다 — 같은 코어의 슬라이드가
셋이면 열마다 다시 받게 되는 자리(105).

막대(그래프)는 **열 중 가장 큰 값을 100** 으로 잡는다. Opal 이 % 라 0~100
눈금이 정직하긴 한데 값이 2~5 % 면 막대가 안 보이고, 이 표는 열끼리
견주는 자리다.

**지금 운영에는 이 줄이 전부 「데이터 없음」 이다.** Opal 이 있는 코어는
RS14-GC04 뿐인데(P17) 그 코어의 슬라이드가 없다. 슬라이드가 있는 코어에
Opal 이 들어오면(지점 화면에서 붙여넣기, P17 5단계) 그때 채워진다 — 사본
DB 에 RS23-GC03 의 Opal 을 임시로 넣어 넷이 다 갈리는 것을 눌러 봤다.

### 열 폭은 쪽에 맞춘다

`table-layout: fixed` 에 `width: 100%` 라 둘을 고르면 두 열이 쪽을 나눠
갖는다. 많이 고르면 `min-width: calc(230px + N × 165px)` 가 열 하나에 165 px
를 지켜 `.scroll` 이 옆으로 민다 — 열 머리가 `RS23-GC03 231cm` 까지 안
잘리는 폭이다. 「비교 대상」 판은 220 px 로 오른쪽에 붙어 스크롤을 따라오고,
800 px 아래에서는 표 위로 올라간다.

## 안 한 것

- 거른 상태를 주소·`localStorage` 에 남기는 것 — 위 이유
- Opal 을 깊이 축 위의 선으로 그리는 것 — 그것은 지점 화면(`/loc/`)이 이미
  한다. 여기는 열끼리 견주는 막대 하나면 된다
- 시야당 개체·파편 비율의 막대 — 수 셋은 머리에 크게 적는 것으로 읽힌다
