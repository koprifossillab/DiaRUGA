# 223 — 판의 검출 지우기를 두 번 눌러야 하게 한다

2026-10-21 · `work/20261021-sclee-ui` · sclee · 앞의 것은 [220](20261008_220_wipe-detections.md)

## 왜

220 의 `S`·`⊘` 는 **한 번에** 지금 판의 검출을 전부 오검출로 돌렸다. 확인 창을
안 둔 근거는 "Ctrl+Z 한 번에 돌아온다" 였다. 그런데 사용자 말로 **스치듯 눌러도
검출이 날아가는 것이 아깝다**(2026-10-21) — 되돌릴 수 있다는 것은 눌렀다는 것을
알아챘을 때의 이야기다. 다른 분류 단축키(`q`·`w`·`e`·`r`·`t`)가 바로 옆이라
잘못 누르기도 쉽다.

## 무엇을

- **`S` 한 번은 불만 켠다.** `⊘` 단추에 빨간 바탕(`.armed` · `--danger`)이 들고,
  상태 줄에 "S(또는 ⊘)를 한 번 더 누르면 이 판의 검출 N개를 전부 오검출로
  지웁니다" 가 뜬다. 아무것도 안 지운다
- **1.5초 안에 한 번 더** 누르면 지운다. Ctrl+Z 한 칸은 그대로다
- **풀리는 자리**: 1.5초가 지나거나, 다른 키를 누르거나. 꾹 눌러 생기는 반복
  입력(`e.repeat`)은 원래 키 처리 맨 앞에서 걸러져 두 번으로 안 친다
- **단추도 같다** (사용자). 키와 단추가 같은 상태(`wipeTimer`)를 쓰므로 `S` 다음에
  `⊘` 를 눌러도 지운다
- 지울 검출이 없으면 불을 안 켜고 "지울 검출이 없습니다" 만 적는다 — 켜 놓고
  두 번째에 아무 일도 안 일어나면 그것이 더 헷갈린다
- 시간이 다 돼 불이 꺼질 때 상태 줄은 **제가 적은 문구일 때만** 지운다. 그 사이
  저장이 "저장됨" 을 적었으면 그쪽을 남긴다

## 버린 것

- **확인 창.** 220 이 일부러 안 둔 것이다 — 판을 자주 지우는 검토자에게 창은
  매번 손을 뗐다 다시 대게 한다. 두 번 누르기는 손이 키 위에 그대로 있다
- **길게 누르기.** 지우는 데 시간이 걸리면 빠르게 훑는 흐름이 끊긴다

## 확인

브라우저 시험(`test_wipe_detections.py`)을 셋 더했다 — 한 번은 안 지운다(불이
CSS 에서 실제로 먹었는지 `getComputedStyle` 로 본다) · 사이에 다른 키를 누르면
풀린다 · 두 번째가 늦으면 안 지운다. 단추 시험도 "두 번 눌러야" 로 바꿨다.
