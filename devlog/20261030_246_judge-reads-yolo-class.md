## 3. 중첩 정리 — SAM 의 규칙이 YOLO 에서 하던 일

`dedupe` 에는 갈래가 둘이다. **거의 같은 짝**(서로 80% 넘게 덮는다)은 하나만 남기고, **집합체**(작은 마스크 둘 이상이
면적의 절반 넘게 설명하는 큰 마스크)는 버린다. 둘 다 SAM 의 다중 스케일 마스크를 치우려고 만들었다.

**거의 같은 짝 — 텍스처가 클래스를 정하고 있었다.** YOLO 는 클래스마다 NMS 를 해서 같은 개체를 봉상과 봉상 파편으로
둘 다 낸다. 텍스처로 고르면 남는 클래스를 엔진의 확신이 아니라 텍스처가 정한다 — 클래스가 다른 짝 149개 중 **78개가
덜 확신한 쪽이 남았다.** 짝은 거의 다 봉상 ↔ 봉상 파편(84) · 원형 ↔ 원형 파편(21) — 4차가 새로 배운 경계다.
**YOLO 면 conf(`predicted_iou`)로 고른다.** 저장된 칸이라 다시 계산해도 같다. SAM 은 텍스처 그대로. 바꾼 뒤 "지운 쪽 conf 가
더 높음" 은 0 이다.

**집합체 — 그때그때 달랐다.** 이 규칙이 지운 153개를 그림으로 뽑았다(NAS `preview/20261030/yolo41-aggregate/` · 빨강이
지운 큰 마스크, 초록이 그 안에서 남은 작은 것들). conf 가 높은 것은 대개 **온전한 개체 하나를 지우고 그 조각들을 남긴**
것이었고, 여러 개체가 붙은 진짜 덩어리를 지운 것도 섞여 있었다 — 사용자가 보고 "그때그때 다르다" 고 했다.

어느 규칙을 걸어도 일부는 틀린다. 그래서 **틀렸을 때 덜 비싼 쪽**을 골랐다(사용자 10-30) — **YOLO 에는 집합체 규칙을 안
건다.** 걸면 틀린 쪽이 탈락 펼침판으로 조용히 숨고, 끄면 큰 것과 조각이 둘 다 화면에 보여 검토자가 그 자리에서 지운다.
v0.38.0 부터 산출은 검토를 마친 시야만 세므로(243) 겹친 채로 개체 수가 부풀지도 않는다. 25장에서 마스크가 장당 6개쯤
는다.

**버린 것** — 집합체 규칙의 방향을 뒤집기(큰 쪽의 conf 가 높으면 작은 쪽을 지운다): 그림에서 conf 로도 갈리지 않았다 ·
예측 단계에서 클래스를 무시한 NMS(`agnostic_nms`): 검출 집합 자체가 바뀌고 학습 때의 조건과 달라진다.

## 4. 옛 파이프라인 이미지에서도 멈추지 않는다

`segment_diatoms.py` 는 `/srv` 의 새 판이 돌지만 모델은 **파이프라인 이미지 안의 것**(`v0.5.3` · 0053 을 모른다)이다.
`engine_cls=` 를 그대로 넘기면 후보를 만드는 순간 `TypeError` 로 죽어 폴러가 멈춘다(198 이 같은 모양이었다).
`engine_kw()` 가 모델에 칸이 있을 때만 싣는다 — 옛 이미지에서는 칸이 `db_default` 로 비고 판정은 형태 규칙으로 간다.
**그래서 4차 클래스가 실제로 저장되려면 파이프라인 이미지를 새로 굽는다**(5절).
