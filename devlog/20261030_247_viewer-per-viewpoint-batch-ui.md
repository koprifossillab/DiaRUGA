243 으로 묶음이 시야마다 정해졌는데 화면은 아직 **전역 검토 대상 하나**를 전제로 말하고 있었다. 시야 목록 머리줄의
"검토 중 yolo-3차", 검토 화면의 엔진 라디오(백엔드 단위로 접어 YOLO 차수가 안 보이고 주 묶음이 무엇인지 안 적힌다)가
그렇다. 그것을 걷는 김에 사용자가 화면을 보며 한 요청을 같이 실었다. 일은 세 갈래로 나눠 했다 — 시야 목록·검토 화면
왼쪽 칸은 이 세션, 엔진 줄·내보내기와 첫 화면은 tmux 세션 둘(worktree 를 따로 두고 브랜치를 갈라 같은 파일을 안
만지게 했다).

## 2. 정한 것과 그 까닭

- **주 묶음은 머리줄이 아니라 표지에 단다.** 한 관찰 안에 3차 정답 시야(`yolo-3차` 에 못 박힘)와 칸이 빈 시야(검토
  대상을 따른다)가 섞인다. 머리줄 한 줄은 어느 한쪽에 대해 거짓말을 한다. 목록·검출 갤러리·계측 표의 머리줄 표시
  (088)는 아직 남아 있다 — 그 화면들도 주 묶음으로 세지만, 이번 요청 범위가 시야 목록이었다(아래 4절).
- **엔진 대신 묶음을 고른다.** 051 이 엔진 단위로 접은 것은 "`yolo-1차`·`yolo-3차` 가 따로 서면 무엇을 눌러야 할지
  모른다" 였는데, 이제는 차수가 곧 비교 대상이다(3차 정답 시야에 4차 출력을 읽기 전용으로 본다 · P31 ⑤). 상자는
  링크이고 떠날 때 `leave()` 를 지난다(116). 주 묶음에 검출이 없으면 개체 0 으로 상자를 둔다 — 4차를 기다리는 칸이
  무엇이 비었는지 적히게.
- **"합성됨" 배지를 걷었다** — 싱글턴이 아니면 전부 합성되어 가르는 것이 없다. 거르기 칩에서도 뺐다.
- **표지의 개수는 둘이다** — 개체(세는 분류 · 파편·미분류를 뺀다)와 전체. 목록 표의 "검출" 칸이 앞엣것이다.
- **판 요약은 왼쪽 칸으로.** 탭 줄 끝에서 한 줄로 잘려 다 읽히지 않았다. 그 자리의 삭제·되살림·분류 지정은 슬라이드
  전체의 수라 시야 목록의 통계 상자로 충분하다.
- **화면 조정의 머리줄 값(`adjnow`)을 걷었다.** 194 가 그것을 둔 까닭(접혀도 켜진 것을 안다)은 머리줄로 올린 되돌리기가
  맡는다 — 100% 가 아니면 색이 들고 `title` 에 값이 적힌다. 채도는 0(흑백)이 뜻 있는 값이라 저장값을 `|| 100` 으로 읽지
  않는다.
- **마우스 조작법은 접지 않고 끝을 줄인다.** 칸이 좁으면 하는 일이 두 줄로 접혀 글쇠와 짝이 안 읽혔다. 칸을 넓히면 다 나온다.
- **첫 화면은 늘 기본값이다**(사용자) — 주소에 인자가 없으면 기억된 보기 방식·범위·코어를 안 읽는다. 기억은 덮지 않는다.
  주소에 값이 있으면 기억대로 연다.
- **해역은 새 칸이 아니라 `Site.region` 이다.** 비어 있던 로스해 넷과 GC03 만 채운다. WAP13 의 "Bigo Bay" 는 사람이 넣은
  값이라 그대로 두었다(사용자) — 첫 화면에서 자기 머리로 따로 선다.
- **지역 이름표는 어디서나 코드다**(사용자: "RS14-GC04면 어디서나 그렇게 불려야 함"). 예전에는 region → name → code 순으로
  골라, 해역을 채우는 순간 "RS14 GC04" 가 "로스해 GC04" 가 될 자리였다. 지점 화면의 「이름」·「해역·지역」 칸과 시스템
  설정 지역 표는 이름표가 아니라 칸의 값이라 그대로 둔다.
