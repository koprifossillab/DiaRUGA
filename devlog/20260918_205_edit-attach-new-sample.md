## 무엇이었나

`/d/<slug>/edit/` 에서 소속 없는 관찰에 지역·지점·시료 코드를 다 채워
저장하면 **행 셋은 생기고 "새로 만들어 붙였습니다" 도 뜨는데 `slide.sample`
은 그대로 비어 있었다.** 063 이 말한 "아무것도 안 한 저장이 성공으로 보이는"
갈래가 하나 남아 있던 것이다.

원인은 한 줄의 자리다.

```python
attached = sample is not None and slide.sample_id != sample.pk   # atomic 앞
```

새로 만든 `Sample` 은 저장 전이라 `pk` 가 `None` 이고, 소속 없는 관찰의
`sample_id` 도 `None` 이라 `None != None` 이 거짓 — `attached` 가 `False` 로
굳는다. 기존 시료에 붙이는 길(`attach_sample`)은 `pk` 가 있어 멀쩡했고, 실제로
소속을 잃었던 `BP09-0901` 도 그 길로 붙였다 — 그래서 여태 안 걸렸다.

## 고친 것

비교를 `sample.save()` **뒤로**, 트랜잭션 안으로 옮겼다. 저장하고 나면 `pk`
가 있으니 `None` 끼리의 비교가 안 생긴다. ForGIA 의 `views.py` 가 이미 그렇게
돼 있어 그대로 맞췄다.

운영 자료는 안 다쳤다 — 사본에서 세어 보니 소속 없는 관찰 0, 관찰 없는 시료 0.
(시료 없는 지점 둘 `GC04`·`GC17` 은 코어 자료만 있는 RS14·RS19 라 원래 그렇다.)

## 시험

`tests/test_dataset_edit.py` — 정보 편집의 붙이기 갈래에 시험이 없었다.
넷을 세웠고 **문구가 아니라 행을 본다**(문구는 버그가 있을 때도 떴다).
고치기 전에 돌려 첫 번째가 `unexpectedly None` 으로 죽는 것을 보고 고쳤다.

- 코드 셋으로 새로 만들어 붙이면 실제로 붙는다 ← 이 버그
- 지역·지점은 있고 시료만 새로 — 위 두 층이 둘로 안 갈라진다
- 기존 시료에 붙이는 길은 그대로
- 이미 붙어 있으면 "붙였습니다" 를 안 낸다
