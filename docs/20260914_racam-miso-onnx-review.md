**작성일** 2026-09-14
**저장소** `github.com:koprifossillab/DiaRUGA`
**근거** 계획 문서 [P27](../devlog/20260914_P27_racam-miso-onnx.md) (2026-09-14 작성)
**검토 대상** <https://github.com/microfossil/particle-classification-onnx>

**상태** **검토 단계 — 착수 전.** 코드는 바꾸지 않았다. 가져올 것 넷을 골라
순서를 매겼다. **그쪽이 적어 놓은 수치는 그쪽 말이다** — 명세 안에서 검산되는
것만 확인했고(1.1절), 우리 자료로 확인한 것은 없다.

이 문서는 P27 을 **지금 시점에서 한 벌로 정리한 것**이다. 판단의 근거와 그쪽
코드의 세부는 P27 본문에 있고, 여기서는 **그쪽이 무엇이고, 우리와 어디가 다르고,
무엇을 어떤 순서로 가져올 것인지**를 본다.

## 1. 그쪽은 무엇인가

Martin Tetard(GNS Science, 뉴질랜드)의 **RaCAM** 과 Ross Marchant 의 **miso-onnx**
가 한 저장소에 있다. 원고는 Biogeosciences 프리프린트(egusphere-2026-2075).

**RaCAM 은 현미경의 C 마운트에 붙는 라즈베리파이 5 카메라**(12.3 MP)이고,
그 위에 두 워크플로가 얹혀 있다.

| 조각 | 무엇 | 크기 | 라이선스 |
|---|---|---|---|
| `miso_onnx/` | 모델 명세(`network_info.xml`) + `model.onnx` 로 **크롭 폴더를 분류**하는 CLI. onnxruntime CPU/CUDA | 파이썬 약 1,300줄 | 명시 없음 (LICENSE 파일이 없다) |
| `RaCAM_IS` | 촬영 → **ImageJ 매크로로 분할·크롭** → `miso-onnx classify` → 크롭을 `<core>/<sample>/<label>/` 폴더로 옮김 → 폴더의 파일 수가 산출표 | 854줄 + 매크로 114줄 | GPL-3.0 |
| `RaCAM_OD` | 촬영 → **YOLO11n ONNX 로 시야 검출** → 주석 이미지 + 시야마다 txt 한 줄 → 산출표. 라이브 검출(표적 종이 보이면 자동 촬영) | 960줄 | GPL-3.0 |
| 동봉 모델 | 남극 신생대 규조 YOLO **9 클래스** · 에오세 방산충 ResNet50 **96 클래스**(정확도 86.1%) | 5.6 MB · 98 MB | 명시 없음 |
| 명세만 | 남극 규조 ResNet50 **39 클래스**, 8,168장, 정확도 97.6%(그쪽 검증 · 1.1절) — 모델 파일은 없다 | — | — |

**자료 층은 파일 이름이다** — `<core>-<sample>-<mag>-<n>.jpg`. DB 가 없고 교정
층이 없고, 분류 결과는 크롭이 어느 폴더에 있느냐다. 그쪽 `core` 는 우리 **지점**,
`sample` 은 **시료**에 해당한다. 관찰·시야·판·교정 층은 그쪽에 없다.

**39 클래스 명세가 눈에 띈다.** 우리 남극(RS23) 시료와 같은 분류군이다 —
*Fragilariopsis curta · kerguelensis · rhombica …*, *Eucampia antarctica*,
*Thalassiosira antarctica* (cold/warm) · *lentiginosa*, *Chaetoceros dichaeta …*,
*Actinocyclus actinochilus*, *Asteromphalus parvulus* 등 30 분류군. 나머지 9 클래스
(`Other - Blurry` 661 · `Other - Double` 982 · `Other - broken` 722 · `Other - Spicule`
836 · `Other - Particle` 328 · `Silicoflagellate` · `Bubble` · `background` · `others`)
는 분류군이 아니고 **학습 자료의 49%** 를 차지한다. 그쪽도 "규조가 아닌 것·흐린
것·겹친 것·깨진 것" 을 분류기가 걸러내게 가르쳤다는 뜻이고, 우리가 P04 에서
**사람이 지운 4,039건을 음성 표본으로 쓴 것**과 같은 자리다.

### 1.1 그쪽 수치를 그대로 믿지 않는다

명세의 수치는 그쪽이 자기 자료로 적은 것이고, 저장소에는 재현할 재료가 없다.
명세 안에서 검산되는 것만 했다.

| 주장 | 확인한 것 |
|---|---|
| 규조 39 클래스 정확도 97.6% | 클래스별 재현율의 가중합과 **일치한다.** 다만 **자기 자료의 20% 를 무작위로 뗀 검증**(1,634장)이고 슬라이드 단위 홀드아웃이 아니다 — 새 슬라이드에서의 값이 아니다 |
| 클래스별 정밀도·재현율 | **39 중 10 클래스가 검증 5장 이하**(2장짜리 셋). 검증의 60% 가 6 클래스이고 그중 셋이 `Double`·`Spicule`·`broken` — 분류군이 아닌 것이 정확도를 떠받친다 |
| 방산충 96 클래스 86.1% | 일치. **F1 이 0 인 클래스 셋**, 검증 5장 이하가 27개 |
| "종 동정 정확도" 인가 | 아니다 — **이미 잘린 크롭**을 분류한 값이다. 분할이 놓친 것은 안 들어간다 |
| YOLO 9 클래스 모델 | **성적이 아예 없다.** Roboflow 자료 이름만 있다 |
| 39 클래스 모델 파일 | **저장소에 없다** — 명세만 있다. 학습 자료도 없다 |
| 프리프린트 | **기술 노트**다. 정확도·mAP·처리량을 안 낸다 |

**그래서 이 문서에서 그쪽 수치를 근거로 쓴 자리는 없다.** 3.3 의 근거는 우리
쪽 6.3% 이고, 크롭 분류기가 우리 자료에서 얼마나 나오는지는 우리가 잰다. 그쪽
명세에서 쓸 것은 수치가 아니라 **모양**이다 — 클래스별 성적을 모델 옆에 두는
형식과, 분류군 아닌 것을 클래스로 넣은 설계. 동봉 YOLO 9 클래스 모델을 RS23
합성본에 돌려 보는 확인은 onnxruntime 이 없어 아직 못 했다 — 3.2 와 함께 한다.

## 2. 우리와 나란히 놓으면

| | RaCAM | DiaRUGA |
|---|---|---|
| 사진이 오는 길 | 카메라가 찍는 순간, 단일 초점 한 장 | Zen 으로 찍은 초점 시리즈가 NAS 로 · 폴러가 합성 |
| 개체 찾기 | ImageJ 문턱·워터셰드 / YOLO11n **상자** | SAM2 → YOLO11m-seg **마스크** (계측이 붙는다) |
| 분류 | **크롭 분류기**(ResNet50, 종까지) | `ClassDef` 7 (유형 넷 + 속 셋). 검출기가 유형을, 사람이 속·종을 — **2단계가 없다** |
| 교정 | 없다 (폴더를 손으로 옮기는 것이 교정) | `ObjectReview`·`DiatomObject` 7,924건, 재생성 불가 |
| 산출물 | **시료 × 분류 표** (CSV) | 시야별 계측 · 카탈로그 · 도감 — **시료 × 분류 표는 아직 없다** |
| 런타임 | onnxruntime (CPU) | torch + ultralytics (GPU 컨테이너) |
| 모델 명세 | `network_info.xml` (클래스별 P/R/F1 까지) | `weights_stamp()` + `PROVENANCE.md` |
| 자료의 원본 | 폴더·파일 이름 | `DiaRUGA.db` |

**카메라 쪽은 겹치는 자리가 없다.** 우리는 촬영이 끝난 사진을 받는 쪽이다.
겹치는 것은 **검출 다음 단계**(분류·산출표)와 **모델을 싣는 방식**(ONNX·명세)이다.

## 3. 가져올 것 넷

### 3.1 시료 × 분류 산출표

행이 시료(남극은 깊이, 육상은 시료 번호), 열이 분류, 값이 개체 수인 표. 그쪽의
최종 산출물이고 미화석 연구의 표준 산출물이다 — P20 의 산출(occurrence) 층이
논문에서 읽어 온 것이 바로 이 표인데 **우리 자료로 만든 표는 아직 없다**
(`TODOs.md` "계측 결과 CSV 내보내기"). 지점 단위 `/locality/<id>/census.csv` 로
내고, 세는 규칙은 새로 적지 않는다 — 카탈로그가 이미 "개체 하나 = 카드 하나" 로
프레임 중복을 접었고(P18·182), `ClassDef.counted`(파편은 안 센다) · `is_taxon` ·
`exclude_from_totals` 가 있다. 유형 표와 종 표 둘로 낸다. 검토 완료 시야만 센다.

### 3.2 검출기를 ONNX 로 내보내 onnxruntime 으로 돌린다

`11m-v1seg-1280.pt` 를 ONNX 로 내보내고 **ultralytics 를 임포트하지 않는** 추론
경로를 만든다. P05(데스크탑 앱) 3단계와 049 §6 의 셋째 선택지가 미뤄져 있던
자리이고, 그쪽 라이브 모드가 그 길을 실제로 밟아 놓았다(ONNX 메타데이터에서
클래스·입력 크기를 읽고 출력을 직접 디코드). 이득은 라이선스가 아니라 **부피** —
torch CPU 휠 수백 MB 가 onnxruntime 수십 MB 로 내려와 설치 파일이 갈라질 이유가
없어진다(우리는 이미 AGPL-3.0 이라 라이선스에는 막히지 않는다).

**함정.** 우리 모델은 seg 라 마스크 계수 × proto 를 곱해 원본 크기로 되돌리는
자리에서 값이 바뀔 수 있다 — `retina_masks=False` 가 모든 개체의 경계를 바꿨던
것과 같은 종류다. 그쪽은 상자 모델이라 이 문제를 안 겪었고, 그쪽 디코드를
그대로 옮기면 안 된다. **torch 경로와 검출 수·`mask_key`·마스크 IoU 를 비교하는
시험부터** 만든다. 서버 파이프라인에서 `--keep-current` 로 나란히 쌓아 뷰어의
엔진 라디오로 본다.

### 3.3 크롭 분류기 — 2단계

검출된 개체의 세운 크롭(카탈로그가 이미 만든다)을 받아 분류를 내는 모델.
지금 개체 14,575 중 **유형이 빈 것이 10,527**, 종명은 168 이다. 09-10 에 엔진
값으로 채워 본 시도는 `judge.classify()` 가 `round`·`rod` 만 가려 사람이 매긴
것에 되돌려 보면 6.3% 만 맞았다 — 유형 판정을 마스크 모양 하나로 하기 때문이고,
속·종은 **크롭의 무늬**로 갈린다. 그쪽이 검출과 분류를 갈라 둔 이유가 그것이다.

| 층 | 클래스 | 지금 있는 자료 |
|---|---|---|
| 유형 | round · round_frag · rod · rod_frag · eucampia · chaetoceros · rhizosolenia (+ 「지운 것」) | 사람이 매긴 약 4,000 + 지운 것 4,039 |
| 종 | 자유 입력 `species` | **168** (Chaetoceros spp. 120 · E. antarctica 31 …) — 아직 못 만든다 |

**첫 판은 유형 7 + 「지운 것」이다.** 그쪽 `Other - Blurry/Double/broken` 이 우리
에겐 지운 개체와 파편 유형이다. 분류기의 답은 **제안이지 판정이 아니다** —
`label` 에 직접 쓰지 않고 `label_suggested`·`suggest_conf` 로 두어 카탈로그
자동완성 순서 · 검토 화면의 옅은 배지 · 검토 순서(확신 낮은 것부터)에 쓴다.
자료 꾸러미는 `ops/export_crops.py` 로 새로 내되 크롭 규칙은 카탈로그와 **한
함수**를 쓰고, 묶인 개체는 대표 하나만 낸다. 어느 판의 크롭을 줄지는 P26(판
선명도)의 답이 정한다.

### 3.4 모델 꾸러미에 딸린 명세

그쪽 `network_info.xml` 은 모델 파일·입출력 모양·**클래스마다 학습 수·정밀도·
재현율·F1**·전처리·학습 자료 출처·추론 시간을 한 파일에 담는다. 우리는 그것이
셋으로 갈려 있고 클래스별 성적이 기계가 읽는 꼴로 없다. `models/<이름>.json`
으로 가중치 옆에 두고 `Run.params` 에 싣는다. 그러면 제안 배지가 "이 클래스는
정밀도 0.69" 를 함께 낼 수 있고, `check_db.py` 가 **모델의 클래스 목록과
`ClassDef` 의 어긋남**을 잡을 수 있다(038 의 "여덟 칸" 함정이 모델 쪽에도 생긴다).

## 4. 안 가져올 것

- **촬영·라이브 검출·Pi 카메라** — 현미경 앞에 사람이 있을 때의 기능. 우리 사진은
  Zen 초점 시리즈로 NAS 에 온다
- **ImageJ 문턱·워터셰드 분할** — 우리가 SAM2 → YOLO 로 대체한 자리
- **폴더·파일 이름을 자료의 원본으로** — 우리는 DB 가 원본이고 이름 규칙은
  `naming.py` 하나뿐
- **Tkinter GUI** — P05 는 PySide6 로 정했다
- **코드 베끼기** — `miso_onnx` 는 LICENSE 가 없고, RaCAM 은 GPL 이라 방향은
  되지만 가져올 만한 코드가 없다. 규칙은 전부 몇 줄이라 우리 자리에 새로 쓴다

## 5. 그쪽에서 본 함정

우리 함정 목록의 같은 줄에 있는 것들이다.

- **화면의 값이 명령에 안 실린다.** `RaCAM_IS` 의 「CNN threshold」 칸은 저장·불러
  오기까지 되는데 실제 분류 명령에 그 인자가 없다. 사람은 문턱을 바꿨다고 믿는다
- **두 경로의 입력이 다르다.** `RaCAM_OD` 라이브는 회색 3채널을, 배치는 컬러를
  같은 모델에 넣는다 — 3.2 의 비교에서 전처리를 같게 못 박고 시작한다
- **분류군이 아닌 것이 산출표의 열이 된다.** 폴더 수를 세므로 `Other - Bubble` 도
  열이다. 우리는 `is_taxon`·`counted` 로 가른다
- **결과 폴더가 곧 교정이라 되돌릴 길이 없다.** 우리 `ObjectReview` 가 이것을
  피하려고 있고, 3.3 에서 제안을 `label` 에 직접 쓰지 않는 이유다
- **의존을 다 끊지 못했다.** `RaCAM_OD` 배치 모드는 여전히 `from ultralytics
  import YOLO` 다. 3.2 에서는 그 경로에 `import ultralytics` 가 없다는 시험을 둔다

## 7. 남은 것 — 사람이 정할 자리

- **육상(BP) 자료를 유형 분류기에 넣나.** 유형 일곱은 권역을 안 가리지만 무늬는
  가린다 — 슬라이드별 분해로 보고 정한다
- **제안을 사람이 `label` 을 적은 뒤에도 남기나.** 남기면 "엔진이 뭐라 했나" 를
  볼 수 있지만 학습 자료를 뽑을 때 섞일 자리가 하나 는다
- **그쪽과 자료를 나눌 수 있나.** 39 클래스 명세의 분류군이 RS23 과 겹친다.
  그쪽 모델은 저장소에 없고 우리 크롭은 그쪽 입력(256×256·단일 초점)과 다르다.
  프리프린트 저자에게 연락할지는 사람이 정한다
- **onnxruntime 을 파이프라인 컨테이너 이미지에 넣나.** 비교 시험이 컨테이너에서
  돌아야 하므로 넣는 쪽이지만 판 올릴 때 정한다
